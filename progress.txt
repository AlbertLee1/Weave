### Key Foundry Facts (do not re-research)
- Wire format: __rid/__primaryKey/__apiName (double underscore) for standard endpoints; $rid for preview multi-type endpoints
- Action path param: {action} (not {actionType}) for execution endpoints; {actionType} for metadata
- Apply options: mode = VALIDATE_ONLY | VALIDATE_AND_EXECUTE; returnEdits = ALL | ALL_V2_WITH_DELETIONS | NONE
- Batch options: returnEdits = ALL | NONE only (2 values, no mode field)
- No separate validateAction endpoint — use apply with VALIDATE_ONLY
- No applyAsync / executeAsync — all sync
- No link write REST — must go through Action rules
- Search/LoadObjectSet select field is REQUIRED
- ListOntologies has NO pagination
- ObjectSet has 15 definition variants (Weave has 9)
- Interface uses dual path: /interfaceTypes/ for metadata, /interfaces/ for data queries
- Attachment is global: /api/v2/ontologies/attachments/... (no {ontology})

### Gotchas
- pkg/oss/handlers_link_crud.go has zero consumers (frontend/SDK/CLI) — safe to delete
- main.go inline aggregate closure duplicates objectset handler — delete it
- Auth middleware must be MiddlewareWithAPIKeys for api-key bearer to work
- TimeSeries path params inconsistent: {property} vs {propertyName} — match Foundry exactly

- When deleting a route: remove from RegisterRoutes, delete handler+service files, update Service interface, clean mock impls in all test files (including pkg/mcp/tools_test.go), remove OpenAPI paths from both yaml files
- OSS Handler setter pattern: SetAggregation — always register the route in RegisterRoutes, return "XxxNotConfigured" error when deps are nil. Wire setters from NewFullRouter before RegisterRoutes call. (SetHistoryRepo/SetBroadcast removed in US-006)
- RegisterRoutes(r, omsHandler) signature — no aiProvider param after US-006. Only V2 read-only routes + query execute remain
- After deleting routes: delete handler + test files, remove handler fields/setters, remove deps.Field from ServerDeps, remove OpenAPI paths + orphaned schemas, update contract test allowlists if needed
- When moving an inline closure from main.go into a handler: update existing tests that relied on the old wiring (e.g. TestAggregationEndpoint_ErrorsAreJSON needed OssSvc after migration)
- ApplyRequest.Options is *ApplyOptions (pointer, omitempty) — nil means use defaults
- Handler resolves options with defaults before calling executor; executor is options-unaware
- VALIDATE_ONLY uses Prepare() only — no CommitBatch, no Publish
- returnEdits=NONE omits edits from response envelope (edits still generated and published internally)
- Old deprecated fields are rejected with 400 + DeprecatedField error code
- Test helpers: setupRouter(), newTestActionType(), mustJSON(), fakePublisher{} in actions_test.go / batch_test.go
- Executor-level tests (batch_test.go) test ApplyBatchAtomic/BestEffort directly; handler-level tests go through HTTP
- Handler layer transforms internal ApplyResult/BatchResult into Foundry OSv2 response envelopes (SyncApplyActionResponseV2 / BatchApplyActionResponseV2)
- countEdits() helper computes ActionResults (addedObjectCount etc.) from []funnel.Edit
- ApplyResult fields have `json:"-"` tags — internal only, not serialized to wire
- Frontend ActionApplyResponse has edits as ActionResults (counts), not individual edit objects
- ActionType.Parameters stored as array in DB: [{"id":"name","type":"string","required":true}] — ToWireJSON() transforms to Foundry V2 record: {"name":{"dataType":{"type":"string"},"required":true}}
- Internal ParseParameterDefs() reads stored array format; wire transformation is in models.go only
- Frontend ParameterForm reads Record<string, ActionParameterV2> with dataType.type for type resolution
- All ByAPIName PG queries use disjunctive dual-accept: `AND (rid = $2 OR api_name = $2)` for the entity param, and `WHERE (ontology_rid = $1 OR ontology_rid = (SELECT rid FROM ontologies WHERE api_name = $1 LIMIT 1))` for the ontology param
- When adding a new method to oms.Repository interface, update ALL mock repos: pkg/oms/handlers_test.go, pkg/actions/actions_test.go, pkg/index/rehydrate_test.go, pkg/links/resolver_test.go, pkg/oss/service_test.go, test/e2e/e2e_test.go, test/chinook/chinook_test.go, test/northwind/northwind_test.go (pkg/mcp/tools_test.go embeds oms.Repository so auto-inherits)
- rid.IsRID(s) checks `strings.HasPrefix(s, "ri.")` — use to distinguish RID from apiName in handlers
- Preview endpoints (interfaceTypes, valueTypes) require ?preview=true — use requirePreview() helper in handlers_v2_metadata.go; queryTypes does NOT require preview
- All V2 routes use `{ontologyApiName}` as the chi URL param name — keep this consistent when adding new routes
- ValueType is global (no OntologyRID) — ListValueTypes() takes no ontology param; GetValueTypeByAPIName uses simple dual-accept (rid OR api_name)
- When adding new V2 read endpoints: add route in routes.go, add path in api/openapi.yaml, copy to cmd/server/openapi_spec.yaml (byte-identical contract test)
- chi routing: register static-segment routes (e.g. byRid, getByRidBatch) BEFORE wildcard routes ({actionTypeRid}) so the wildcard doesn't swallow them
- ActionType has two serialization methods: ToWireJSON() for basic list format, ToFullMetadataJSON() for everything (rules, submissionCriteria, etc.)
- ObjectType has two serialization methods: ToWireJSON() for basic list format, ToFullMetadataJSON() for everything (properties with full detail, icon, color, etc.)
- Foundry batch-by-RID pattern: silently skip missing RIDs, return only found entries; reuse getByRidBatchRequest type across ActionType/ObjectType
- ObjectType fullMetadata handler loads properties via ListProperties(ctx, ot.RID) before serialization — properties are not auto-loaded on GetObjectTypeByAPIName
- For optional-presence JSON request fields, use *json.RawMessage — nil if key absent, non-nil (even empty `{}`) if present
- ObjectSet handler endpoints live in pkg/oss/objectset/handler*.go — new endpoints for objectSets go here, not in pkg/oss/handlers.go
- LoadLinks reuses searchAround executor internally — to add link-based ObjectSet endpoints, compose a searchAround Definition and pass to executor.Execute()
- Foundry V2: select is REQUIRED in SearchObjectsRequestV2 and LoadObjectSetRequestV2 — missing/empty returns 400 with SelectRequired error
- Frontend callers (BrowserPage, ObjectSetResults) must derive select from objectType.properties before calling search/loadObjects
- ObjectSetResults resolves the static root type name from the ObjectSet definition, fetches type metadata, then passes its property keys as select
- fullMetadata endpoints (objectType, actionType, actionTypesFullMetadata, ontology) all require ?preview=true — use the existing requirePreview() helper in handlers_v2_metadata.go
- ObjectType.status Foundry values: ACTIVE, ENDORSED, EXPERIMENTAL, DEPRECATED — migration 000014 maps PROMOTED→ENDORSED, EXAMPLE→EXPERIMENTAL
- When adding a REQUIRED field to a handler: update ALL test bodies in test/e2e/, test/northwind/, test/chinook/ that call that endpoint
- Python SDK search() now requires `select` keyword arg — callers must provide property list
- When adding a new method to oss.Service interface, update fakeOssService in pkg/mcp/tools_test.go
