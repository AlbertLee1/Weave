### Codebase Patterns
- Action rules in pkg/actions/rules.go — ExecuteRules() dispatches by rule type
- CollapseEdits in pkg/actions/collapse.go — dedup per (objectType, primaryKey); link edits keyed by (linkTypeRID, sourcePK, targetPK)
- Internal edit type pattern: editTypeUpsert (UPSERT) is internal to actions pkg, resolved in Executor.Prepare before publishing
- ObjectExistenceChecker interface on Executor: injected like FunctionDispatcher, nil→graceful default to CREATE
- Interface-backed rules: objectType resolved from params via resolveObjectTypeParam ("objectType" or "objectTypeApiName"); validated in Executor.Prepare after ExecuteRules
- Validation requiring OMS repo (interface membership, link type resolution) happens in Executor.Prepare, not in ExecuteRules (keeps ExecuteRules pure)
- bleveObjectChecker (in integration tests) wraps index.Manager + ontologyAPIName for existence checks via idx.Document(pk)
- Where operators in pkg/oss/where/converter.go — ConvertToBleveQuery switch on type
- Aggregation metrics in pkg/oss/aggregation/engine.go — switch on AggregationSpec.Type
- OMS models in pkg/oms/models.go — all entity structs
- OMS repository interface in pkg/oms/repository.go — ~60 methods
- Migrations in migrations/ — sequential 000001-000023, next is 000024
- ObjectFetcher interface on Executor: injected like ObjectExistenceChecker, nil→graceful degradation (PrevEdits omitted)
- PrevEdits is a parallel slice to Edits in PreparedAction; serialized to ActionLog.PrevEdits JSONB (null entries for CREATE/LINK edits)
- Frontend routes in web/src/App.tsx
- API hooks in web/src/hooks/
- Sidebar nav in web/src/components/layout/Sidebar.tsx
- Link edits (LINK_CREATE/LINK_DELETE) flow: Rule → Edit → NATS → Consumer.applyLinkCreate/applyLinkDelete → UpsertLinkEdge/DeleteLinkEdge
- Consumer has separate LinkEdgeWriter (SetLinkEdgeWriter) and LinkEdgeDeleter (SetLinkEdgeDeleter) interfaces for M2M edge writes/deletes
- Executor.Prepare resolves link type API names to RIDs via GetLinkTypeByAPIName before publishing
- Pre-existing build errors in pkg/oms/admin_handlers.go and execute_query_goja_test.go — not blocking tests in other packages
- Revert logic in pkg/actions/revert.go — generateReverseEdits maps CREATE→DELETE, MODIFY→MODIFY(prevState), DELETE→CREATE(prevState), LINK_CREATE→LINK_DELETE, LINK_DELETE→LINK_CREATE
- AlreadyRevertedError sentinel type for 409 Conflict on double-revert
- Repository additions: GetActionLog(id) and UpdateActionLogStatus(id, status) — added to oms.Repository interface + PG impl + all mocks
- OpenAPI spec lives in api/openapi.yaml AND must be copied to cmd/server/openapi_spec.yaml; contract tests enforce this (TestContract_AllRoutesDocumented, TestContract_EmbeddedSpecMatchesCanonical)
- Bleve GeoShapeQuery (v2.5.7) works on GeoShape-indexed fields, not geopoint fields; for point data, use PointInPolygon in-memory fallback
- Geo tests use setupGeoIndex() with NewGeoShapeFieldMapping() to index GeoJSON Point features for polygon query testing
- doesNotIntersect* operators: negate via BooleanQuery(MatchAll + MustNot(inner)); for BoundingBox use GeoShapeQuery("polygon","intersects") over GeoBoundingBoxQuery for GeoShape field compat
- PolygonQuery input format: {"polygon": [[[lon,lat],...]] } — GeoJSON Polygon coordinates; converted to [][][][]float64 for Bleve
