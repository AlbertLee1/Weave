## Codebase Patterns
- New apierror status code: add a constructor in `pkg/apierror/error.go` next to the existing `NewNotFound` / `NewBadRequest` family — use uppercase-snake `ErrorCode` (e.g. `WEAVE_VALIDATION_ENUM`), pick an http.Status* constant, and the wire format / WriteJSON path picks it up automatically. No extra plumbing needed.
- Surfacing typed `*apierror.APIError` from action validation: return the APIError directly from the validator (e.g. `validateValueTypeConstraints`); Prepare wraps it with `fmt.Errorf("...: %w", err)` so `errors.As` still finds it. Handlers MUST then check `errors.As(err, &apiErr *apierror.APIError)` BEFORE wrapping into the legacy `ActionFailed` 400 — otherwise the typed status code + structured Parameters are lost.
- `BatchError` (pkg/actions/executor.go) needs a `Cause error` field + `Unwrap()` method to propagate typed errors from Prepare through `ApplyBatchAtomic`. Without it the batch path collapses every prepare failure into a generic 400, masking 422/409/403 distinctions. Update both BatchError construction sites (publish failure + per-action prepare failure) when adding a new typed validation error.
- Typed constraint errors (`types.EnumViolationError`): when ValidateConstraints needs to surface structured detail (allowed values, rejected value), define a typed error in `pkg/types/constraints.go` with public fields, return it from the relevant branch, and keep `Error()` returning the legacy string. Callers detect via `errors.As` and ignore the string. Don't try to parse fields out of `err.Error()` — that path always loses fidelity.
- Goja sandbox recipe (reusable for derived props / formulas): call `vm.Set(name, goja.Undefined())` then `vm.GlobalObject().Delete(name)` for each denied host global; add watchdog goroutine that does `vm.Interrupt(...)` when `context.Done()` fires.
- Read-only object views in Goja: implement `goja.DynamicObject` and keep a reference to the owning `*goja.Runtime` so `Get` can return `runtime.ToValue(v)` from the same VM — returning values from a different runtime crashes Goja.
- Goja `Callable` from `goja.AssertFunction` is a Go `func(this Value, args ...Value) (Value, error)`; do NOT try to `.Get("call")` and re-invoke — just call it directly.
- `properties` table columns land via an ALTER with `ADD COLUMN IF NOT EXISTS ... NOT NULL DEFAULT ...`; matching `pg_repository.go` helpers must add the column to INSERT, SELECT (ListProperties + GetProperty) and UPDATE paths, in that order.
- `Property` model (pkg/oms/models.go) is the canonical wire shape; adding an omitempty JSON-tagged field is non-breaking for every existing test.
- `pkg/oss.WireObject.MarshalJSON` flattens Properties to the row's top level alongside `__primaryKey` / `__apiName`; HTTP tests of loadObjects must decode rows as `map[string]interface{}` and read fields directly, not as `row.Properties[...]`.
- Goja exports whole-number JS arithmetic results as Go `int64` and fractional ones as `float64`. Tests on derived-property numerics should accept either (via a `toFloat64` helper) rather than assert a single concrete type.
- Executor-level "load base object fields" is a single `bleve.DocIDQuery` with `Fields=["*"]` and `Size=len(pks)`. Batch once per withProperties invocation and share across DPs — per-row Bleve queries were the original pattern and are materially slower at scale.
- New OMS resource types with their own table: DON'T extend `oms.Repository`. ~15 mock implementations across pkg/{oms,oss,links,actions,index,automate,ai}, test/{northwind,chinook,e2e,fixtures,integration} would need new stubs. Instead add a narrow interface in the same package (e.g. `ComputedPropertyStore`) and expose CRUD directly on `*PGRepository`.
- TTL-cache tests: inject a clock via `SetNowFunc(func() time.Time)` + an advance helper. Matches `oms.CachedRepository.nowFunc` convention and keeps time-based tests deterministic without calling `time.Sleep`.
- JSONB round-trip in pgx: stage through `[]byte` (`var aggJSON []byte` → `json.Unmarshal`). Passing the struct directly to `rows.Scan` will fail.
- Adding a new BaseType: update (1) `allBaseTypes` map + slice in pkg/types/basetype.go, (2) the count + slice in `TestBaseType_AllDefined`, (3) per-language maps in pkg/sdkgen/typemap.go (ts/python/go). Coerce/Validate have catch-all default branches so opaque types need no work there.
- Content-addressed blob storage: hash + write in one pass via `io.MultiWriter(tempFile, sha256.New())`, then CAS under a mutex — `os.Stat` the destination; if present drop the temp and reuse, else `os.MkdirAll` + `os.Rename`. Never hash a second time from disk.
- Path-traversal guard for FS-backed stores: clean the input (`filepath.Clean(filepath.FromSlash(p))`), reject if it starts with `..` or is absolute, then verify `filepath.Abs(resolved)` is under `filepath.Abs(root)+sep`. Single choke point — duplicate nowhere.
- Multipart upload size cap: wrap `r.Body = http.MaxBytesReader(w, r.Body, max)` BEFORE `ParseMultipartForm`, then check `errors.As(err, &maxErr)` against `*http.MaxBytesError` to distinguish "too large" from generic parse errors. The cap applies to the WHOLE request body (parts + boundary + form fields), so set the limit slightly above the per-file budget if you need exact per-file enforcement.
- New global blob-style API endpoints (no {ontology} segment) belong inside the `r.Group(... auth.MiddlewareFull ...)` block in cmd/server/main.go but mount conditionally: `if deps.MediaStore != nil && deps.MediaCatalog != nil { ... }`. In main.go, capture `pgRepo := oms.NewPGRepository(pool)` BEFORE wrapping so you can hand the bare repo to deps.MediaCatalog / deps.ComputedPropertyStore.

Two accepted shapes: `{__type: "<variant>", value: <v>}` (universal wrapper — coerce emits this form) OR `{__type: "<variant>", ...structFields}` (flattened tagged struct — read path recognizes it via "key count != 2" heuristic). - Nullable text column in Go: `NULLIF($N, '')` on INSERT / UPDATE + `COALESCE(col, '')` on SELECT keeps the Go model a plain `string` (no `sql.NullString`) while the DB carries proper NULLs so partial indexes `WHERE col IS NOT NULL`, self-referential FKs and data-quality checks still work. Every `COALESCE(description, '')` in pg_repository.go is prior art — follow the same shape for any new nullable text.
- Optional field on Update DTO: use `*string` (or `*bool` etc) so callers can distinguish three states — omit=preserve, `""`=clear, `"X"`=assign. Bare `string` collapses "omit" and "clear" into one, silently nuking existing data whenever a client sends a partial update. `UpdateLinkTypeRequest.IsRequired *bool` is prior art.
- Self-referential FK in schema: prefer NULLable-without-REFERENCES for pair-authoring workflows where both sides are created separately (A↔B bidirectional links, parent/child before-both-exist, etc). Handler-layer validation enforces symmetry invariants; the DB accepts a temporary dangling reference during authoring. REFERENCES would require deferred constraints or a magic create-order — more surface area than it's worth when validation is already centralized.
- Adding a new route to `cmd/server` is a 3-step sync: (1) `RegisterRoutes` in `cmd/server/routes.go`, (2) matching `paths:` entry in `api/openapi.yaml`, (3) copy canonical to embedded: `cp api/openapi.yaml cmd/server/openapi_spec.yaml`. The `TestContract_*` trio fails otherwise with a precise "missing entries" diagnostic — friendly, non-ambiguous.

Emulating reverse by filtering a forward call silently returns wrong rows. Pattern generalizes to any adjacency-list traversal where direction matters.

The legacy column stays the lowest-common-denominator handle for ~all downstream consumers (Bleve doc IDs, FK lookups, mock repos), the new column carries the full model. Single decodePrimaryKeyProps-style helper at every Scan site falls back to wrapping legacy in a one-element slice — keeps the read path tolerant of partially-migrated rows without scattering nil-checks.
- Composite-key URL routing (`/objects/{objectType}/{key1}:{key2}`): chi treats `:` as opaque path char. NO router changes needed; handler reads the raw segment and `oms.ParseCompositeKey(raw, expected)` is the canonical splitter, gated on `expected > 1` so single-PK ObjectTypes keep colon-bearing keys (e.g. RIDs) intact.
- Single-parent inheritance "diamond detection" reduces to chain-cycle detection. `extends_rid` is one column → only A→B→A loops are reachable; `oms.ValidateInheritanceCandidate(repo, otRID, parentRID)` walks the candidate parent's chain checking the visited set (seeded with `otRID`) and returns `oms.ErrInheritanceCycle` on the first repeat. The read-side resolver (`ResolveInheritedObjectType`) carries the same guard so stale data can't spin the merge forever.
- Inheritance import remap: when CreateOntology copies object types into a fresh ontology, ExtendsRID may point at any other type in the same import — including one that appears later in the slice. Pre-allocate new RIDs for the whole slice into otRIDMap BEFORE the create loop so parent pointers can be remapped regardless of declaration order. Same shape works for any future self-referential field on a row that imports as a batch.
- pkg/oms needs to call into pkg/actions (e.g. polymorphic invoke forwarding to the ActionExecutor): declare a NARROW interface in pkg/oms (`oms.InterfaceMethodActionDispatcher`), keep pkg/oms free of any pkg/actions import, and put the concrete adapter inside `cmd/server/`. Same trick as `pgEdgePropertiesResolver` from US-210 — keeps the dependency direction clean AND makes degraded-mode test routers trivial (no dispatcher wired ⇒ resolution still works, execution just skipped).
- When a handler under test relies on `mockRepo` methods that other tests stubbed as "return nil/createErr", promote them to real in-memory implementations (e.g. add an `interfaceAttachments []ObjectTypeInterface` slice in `handlers_test.go` so `AttachInterface` / `ListObjectTypeInterfaces` actually persist). Zero-arg stubs silently hide missing data and your new test passes by accident. The promotion is additive — existing tests that only read nil stay green.
- NOT NULL DEFAULT '{}'::jsonb columns: read path MUST `COALESCE(col, '{}'::jsonb)` AND write path MUST substitute '{}' for nil json.RawMessage — pgx encodes nil json.RawMessage as the string "null", which the JSONB column happily accepts but breaks the "empty ⇒ nil-on-the-wire" round-trip. Single normalise/decode helper pair (see `pkg/oms/function.go` normaliseSignatureForWrite + signatureFromBytes) keeps both sides honest.
- Idempotent CHECK constraint additions in migrations: ALTER TABLE … ADD CONSTRAINT has no IF NOT EXISTS for CHECKs (unlike COLUMNS), so wrap with `DO $$ BEGIN IF NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname = '...') THEN ALTER ... END IF; END$$;`. Prior art: `migrations/000040_function_signature_runtime.up.sql` for `functions_runtime_check`.
- Typed parameter-validation errors for HTTP handlers: define a struct error (`oms.FunctionParamError{Parameter, Code, Reason}`) so the handler can `errors.As` and emit a structured 400 with `parameter`+`code`+`reason` instead of a free-form message string. Convention: `Code` ∈ a small closed enum (`missing_required`, `type_mismatch`, `unknown_parameter`, `default_invalid`); SDKs key off `code` and ignore the human `reason`. Same shape used by `types.EnumViolationError` (US-052) — the validator owns both the legacy `Error()` string AND the public fields, so callers that haven't migrated to `errors.As` keep seeing a sensible message.
- "No-contract opts out of validation" semantic: when the declared signature is empty (nil / "{}"), the validator MUST pass every input through unchanged — including unknown keys. This matches the principle that a Function without a signature is "untyped" and the executor will receive whatever the caller sent. Once a signature exists, it becomes the gate. Making the empty case strict (reject unknowns even with no contract) breaks every legacy function authored before signatures landed; making it permissive when the signature IS declared loses the whole point. Test both directions.

  - Content-addressed dedup is cheapest done at Put time: hash + write in the same io.Copy (via MultiWriter), then compare-and-swap under a mutex. Do NOT scan the temp file back to rehash after the fact — that doubles I/O and races with concurrent uploads.

  - `DataType` was designed to be extensible via JSON fields (SubType, Fields, Precision, Scale, now Variants). Keep both patterns separate: structural-keys are write-once, relational/metadata pointers can be retargeted.

Keep them addressable as distinct resources.
  - `pkg/oms.inheritanceReader` is a narrow 3-method subset of `oms.Repository` (GetObjectType + ListProperties + ListOutgoingLinkTypes). Defining it locally to the resolver keeps the unit tests trivial — every existing mockRepo already satisfies it implicitly — and signals which methods the resolver actually consumes when reading the function signature.
  - Field-on-existing-struct additions (no new method on Repository) are zero-touch for the ~15 mockRepo / inMemoryOmsRepo stubs across the test tree. Struct-value maps copy the new field for free; only manual struct literals that pin every field would need updating, and the codebase doesn't have any of those.

- **Learnings for future iterations:**
  - The "runtime validator" for any signature-typed surface (functions, action params, automate effects) follows the same shape: PARSE the signature into a typed Go view → for-each declared param check required/default/type → reject unknown keys → return a fresh map. Don't try to bolt validation onto the shape-checker (`ValidateFunctionSignature`); the shape checker validates the SIGNATURE, the parameter validator validates VALUES against an already-valid signature. Two responsibilities, two functions.
  - When a typed error needs both a structured payload (for handlers to map to 400) AND a legacy Error() string (for log lines / non-handler callers), define a small struct with public fields + a tight Error() method. `oms.FunctionParamError` and `types.EnumViolationError` (US-052) both follow this shape — handlers do `errors.As(err, &pe)` then read `pe.Code` / `pe.Parameter` directly.
  - `apierror.NewInvalidParameter("InvalidParameter:"+paramName, map[string]string{...})` is the canonical shape for "validation rejected the user's value". The ErrorCode carries the parameter name as a suffix so log filters can grep for a specific bad-input by name; the Parameters map carries `parameter`+`code`+`reason` so structured consumers don't have to parse the code suffix.
  - For optional executor-style hooks (`SetFunctionExecutor`, `SetQueryExecutor`, `SetLinkPropertyStore`), the right degraded-mode response is NOT a generic 500 — it's a 503 with whatever pre-execution work IS available echoed in the body. Here the validator runs to completion regardless of executor state, so the 503 response can still tell the caller "your params are valid; we just can't execute right now." Friendly to clients debugging in non-prod environments.
  - Empty body handling in ExecuteFunction: `r.ContentLength == 0` short-circuits before `ReadJSON` so the handler tolerates `POST .../execute` with no body at all (callers MAY pass an empty body when every param has a default). Naive `ReadJSON(r, &body)` against a nil body errors out with "EOF" — guard it.
  - Test the "no contract" / "with contract" boundary explicitly. The "no signature ⇒ accept everything" rule is easy to forget: it's tempting to make the validator strict-by-default, but every legacy Function predates US-215 and has no signature, so a strict-by-default validator silently breaks them all. Two test cases (no-contract pass-through + unknown-rejected-when-contract-declared) lock the right semantics.
