### Codebase Patterns
- Action rules in pkg/actions/rules.go — ExecuteRules() dispatches by rule type
- CollapseEdits in pkg/actions/collapse.go — dedup per (objectType, primaryKey); link edits keyed by (linkTypeRID, sourcePK, targetPK)
- Internal edit type pattern: editTypeUpsert (UPSERT) is internal to actions pkg, resolved in Executor.Prepare before publishing
- ObjectExistenceChecker interface on Executor: injected like FunctionDispatcher, nil→graceful default to CREATE
- Interface-backed rules: objectType resolved from params via resolveObjectTypeParam ("objectType" or "objectTypeApiName"); validated in Executor.Prepare after ExecuteRules
- Validation requiring OMS repo (interface membership, link type resolution) happens in Executor.Prepare, not in ExecuteRules (keeps ExecuteRules pure)
- bleveObjectChecker (in integration tests) wraps index.Manager + ontologyAPIName for existence checks via idx.Document(pk)
- Where operators in pkg/oss/where/converter.go — ConvertToBleveQuery switch on type; ConvertToBleveQueryWithOpts for fuzzy-enabled conversion
- Fuzzy search: MatchQuery.SetFuzziness(n) on text operators; options threaded via ConvertOptions through logical operators
- Aggregation metrics in pkg/oss/aggregation/engine.go — switch on AggregationSpec.Type
- OMS models in pkg/oms/models.go — all entity structs
- OMS repository interface in pkg/oms/repository.go — ~60 methods
- Migrations in migrations/ — sequential 000001-000029, next is 000030
- AutomationRule/AutomationExecution models in pkg/oms/models.go; PG CRUD in pg_repository.go; mock stubs in mock_automation_test.go per package
- Automation mock stubs pattern: same as branches/proposals — mock_automation_test.go per package (pkg/oms, pkg/actions, pkg/oss, pkg/links, test/e2e, test/northwind, test/chinook) + inline in pkg/index/rehydrate_test.go
- Scheduler pattern: pkg/automate/scheduler.go — RuleLoader + ExecutionRecorder interfaces; robfig/cron/v3 for cron scheduling; entries map[string]cron.EntryID tracks active rules
- ScheduleTriggerConfig: { "cron": "*/5 * * * *" } — supports standard cron + robfig extensions (@every, @hourly, etc.)
- Watcher pattern: pkg/automate/watcher.go — DataChangeRuleLoader + ExecutionRecorder + optional ObjectPropertyFetcher; HandleChangeEvent callback for funnel.ChangeEvent
- DataChangeTriggerConfig: { "objectType": "Employee", "editTypes": ["CREATE","MODIFY"], "where": {...}, "debounceMs": 0 }
- Watcher debounce: per-ruleID time.AfterFunc timer; DebounceMs=0 → immediate; >0 → resets on each matching event, fires with last event
- Effects pattern: pkg/automate/effects.go — Effect struct (type, actionTypeApiName, functionRid, parameters), ActionApplier + AutomateFunctionDispatcher interfaces, TriggerEventData for template resolution
- Effect types: "executeAction" (US-128), "executeFunction" (US-129), "notification" (US-130) — processEffects dispatches by type
- Template variables: ${event.primaryKey}, ${event.editType}, ${event.objectType}, ${event.properties.fieldName} — resolved via resolveTemplateString before passing to ActionApplier
- Chain template variables: ${effects[N].result} — resolved via resolveTemplateStringWithChain; allows later effects to reference earlier effect results
- ActionApplier interface: ApplyAction(ctx, ontologyRID, actionType, parameters) error — wrap actions.Executor.Apply for use with automation
- AutomateFunctionDispatcher interface: DispatchFunction(ctx, functionRid, parameters) (interface{}, error) — delegates to GojaDispatcher or HTTPDispatcher
- Both Scheduler and Watcher have SetActionApplier, SetFunctionDispatcher, and SetNotificationCreator methods; nil → effects silently skipped
- EffectResult struct: holds result from each effect execution; processEffects returns []EffectResult for chain support and storage
- Function results stored in automation_executions.result JSONB column (migration 000027); serialized as []EffectResult JSON array
- executeRule now passes ontologyRID (from AutomationRule) through closure to processEffects
- NotificationCreator interface: CreateNotificationForUser(ctx, userID, title, body, nType, link) error — implemented by OMSHandler; delegates to repo.CreateNotification
- Notification model in pkg/oms/models.go; PG CRUD in pg_repository.go; mock stubs in mock_notifications_test.go per package
- pkg/oms cannot import pkg/auth (circular: auth→oms via policy_evaluator.go); use ActorFunc pattern for user ID extraction
- OMSHandler.actorFn: injected function for extracting user ID from request context; nil→"dev-user" fallback
- RetryPolicy pattern: pkg/automate/retry.go — RetryPolicy struct (MaxRetries, BackoffMs); ParseRetryPolicy from json.RawMessage; BackoffDuration exponential (backoffMs * 2^attempt)
- Retry in Scheduler/Watcher: executeAttempt recursive method; first attempt → InsertExecution, subsequent → UpdateExecution; time.AfterFunc for async retry
- ExecutionRecorder interface: InsertExecution + UpdateExecution; both Scheduler and Watcher use this
- ListExecutions handler: in-process filter (?status=) + pagination (?limit=, ?offset=); response includes total/offset/limit metadata
- processEffects signature: 7 params (ctx, effects, ontologyRID, data, applier, funcDispatcher, notifier)
- Effect failure: processEffects returns error → execution recorded with status="error" and error message
- Scheduler dynamic updates: AddRule, RemoveRule, PauseRule (alias for RemoveRule), ResumeRule (alias for AddRule)
- OntologyBranch/BranchChange models in pkg/oms/models.go; PG CRUD in pg_repository.go (CreateBranch, GetBranch, ListBranches, CloseBranch, CreateBranchChange, ListBranchChanges)
- Branch mock stubs pattern: create mock_branches_test.go in each package (pkg/oms, pkg/actions, pkg/oss, pkg/links, test/e2e, test/northwind, test/chinook, pkg/index/rehydrate_test.go inline)
- Proposal mock stubs pattern: same as branches — mock_proposals_test.go per package; proposal models have branch_id FK
- OntologyProposal/ProposalReview models in pkg/oms/models.go; PG CRUD in pg_repository.go; handlers in handlers_proposal.go
- ObjectFetcher interface on Executor: injected like ObjectExistenceChecker, nil→graceful degradation (PrevEdits omitted)
- PrevEdits is a parallel slice to Edits in PreparedAction; serialized to ActionLog.PrevEdits JSONB (null entries for CREATE/LINK edits)
- WebSocket Hub pattern: pkg/subscriptions/hub.go — Hub manages connections map; per-connection context derived from Hub context; readPump cancel triggers writePump exit; Hub.Close cancels context + closes all connections
- WebSocket auth pattern: pkg/subscriptions/handler.go — TokenValidator func(token)(userID, error); nil validator = dev mode (accept all); ?token= query param validated before websocket.Accept upgrade
- WebSocket route registered directly in NewFullRouter (not RegisterRoutes) because it's outside the auth middleware group
- Subscription pattern: pkg/subscriptions/subscription.go — Subscription struct with ID/ObjectType/Where/Select; Matches() evaluates objectType + where.MatchClause; ProjectProperties() filters by Select clause
- Subscribe/Unsubscribe: handleSubscribe/handleUnsubscribe on Hub; dispatched from readPump via Message.Type switch
- Connection.subscriptions: map[string]*Subscription with separate subMu lock; max 10 per connection (MaxSubscriptionsPerConnection)

- ObjectChangeEvent: { state: "ADDED_OR_UPDATED"|"DELETED", object: {...} } — CREATE/MODIFY→ADDED_OR_UPDATED, DELETE→DELETED
- Frontend routes in web/src/App.tsx
- API hooks in web/src/hooks/ — useWebSocketSubscription for WS real-time; useObjectSetSubscription for SSE fallback
- Frontend WebSocket hook pattern: useWebSocketSubscription(ontology, { objectType, where?, select?, enabled, onEvent }) — auto-reconnect with exponential backoff; subscribes after welcome; dispatches objectChanged data

- Sidebar nav in web/src/components/layout/Sidebar.tsx
- Link edits (LINK_CREATE/LINK_DELETE) flow: Rule → Edit → NATS → Consumer.applyLinkCreate/applyLinkDelete → UpsertLinkEdge/DeleteLinkEdge

- Geo tests use setupGeoIndex() with NewGeoShapeFieldMapping() to index GeoJSON Point features for polygon query testing
- doesNotIntersect* operators: negate via BooleanQuery(MatchAll + MustNot(inner)); for BoundingBox use GeoShapeQuery("polygon","intersects") over GeoBoundingBoxQuery for GeoShape field compat
- PolygonQuery input format: {"polygon": [[[lon,lat],...]] } — GeoJSON Polygon coordinates; converted to [][][][]float64 for Bleve
- Branch overlay pattern: validateBranch(w,r) checks ?branch= param; writeBranchChange(ctx, branchID, changeType, entityType, entityRID, before, after) serializes and records; Update handlers use copy-then-modify (updated := *existing) to preserve before_state

- OpenAPI responses: ConflictError (409) and PermissionDeniedError (403) defined in components/responses
- Branch merge: MergeProposal handler in handlers_proposal.go; detectConflicts compares branch beforeState with current main entity JSON (semantic equality via reflect.DeepEqual on unmarshaled maps)
- UpdateBranchStatus(ctx, id, status) — generic status update for branches; CloseBranch only sets "closed", UpdateBranchStatus can set any status
- json:"-" fields (OntologyRID) must be restored when applying ADDED/MODIFIED branch changes to main — applyAdd/applyModify set ontologyRID explicitly
- jsonEqual helper: unmarshal both sides to interface{} and reflect.DeepEqual for order-independent JSON comparison
- Conflict detection only triggers when ontologyVersion > branch.BaseVersion; entity-level comparison via fetchEntityJSON (GetObjectType/GetProperty/GetLinkType/GetActionType by RID → marshal → compare)
- MergeConflict response: {errorCode: "MERGE_CONFLICT", conflicts: [{entityType, entityRid, changeType, branchState, mainState}]}
- applyBranchChanges dispatches by (changeType, entityType) → CRUD operations on main tables; ADDED→Create, MODIFIED→Update, DELETED→Delete
- Rebase reuses detectConflicts from merge; on success updates base_version + before_state of MODIFIED/DELETED changes
- UpdateBranchBaseVersion and UpdateBranchChangeBeforeState — new Repository methods for rebase support
- OntologyExport model in pkg/oms/models.go — full export struct with 10 entity types; used by V2 export endpoint, admin export, GetFullMetadata, and snapshot serialization
- ExportOntologyV2 handler in pkg/oms/handlers.go — fetches all entities by ontologyRID; ListValueTypes is global (no ontologyRID param)
- TypeScript SDK shape (pkg/sdkgen/gen_ts.go): WeaveClient exposes `readonly {ObjectType}: {ObjectType}Repository` per type; each Repository has get/list/search and `readonly linkedObjects: {ObjectType}LinkedObjects`; LinkedObjects has one method per outbound LinkType returning `{data: TargetType[]}`; Action methods stay on WeaveClient as `apply{ActionName}`
- SDK generator integration tests use `//go:build integration` tag; tsc resolved from web/node_modules/typescript/bin/tsc with PATH fallback (skip if missing); mypy resolved from PATH (install via `pip install --user mypy pydantic httpx`)
