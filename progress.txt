## Codebase Patterns
- Goja sandbox recipe (reusable for derived props / formulas): call `vm.Set(name, goja.Undefined())` then `vm.GlobalObject().Delete(name)` for each denied host global; add watchdog goroutine that does `vm.Interrupt(...)` when `context.Done()` fires.
- Read-only object views in Goja: implement `goja.DynamicObject` and keep a reference to the owning `*goja.Runtime` so `Get` can return `runtime.ToValue(v)` from the same VM — returning values from a different runtime crashes Goja.
- Goja `Callable` from `goja.AssertFunction` is a Go `func(this Value, args ...Value) (Value, error)`; do NOT try to `.Get("call")` and re-invoke — just call it directly.
- `properties` table columns land via an ALTER with `ADD COLUMN IF NOT EXISTS ... NOT NULL DEFAULT ...`; matching `pg_repository.go` helpers must add the column to INSERT, SELECT (ListProperties + GetProperty) and UPDATE paths, in that order.
- `Property` model (pkg/oms/models.go) is the canonical wire shape; adding an omitempty JSON-tagged field is non-breaking for every existing test.
- `pkg/oss.WireObject.MarshalJSON` flattens Properties to the row's top level alongside `__primaryKey` / `__apiName`; HTTP tests of loadObjects must decode rows as `map[string]interface{}` and read fields directly, not as `row.Properties[...]`.
- Goja exports whole-number JS arithmetic results as Go `int64` and fractional ones as `float64`. Tests on derived-property numerics should accept either (via a `toFloat64` helper) rather than assert a single concrete type.
- Executor-level "load base object fields" is a single `bleve.DocIDQuery` with `Fields=["*"]` and `Size=len(pks)`. Batch once per withProperties invocation and share across DPs — per-row Bleve queries were the original pattern and are materially slower at scale.
- New OMS resource types with their own table: DON'T extend `oms.Repository`. ~15 mock implementations across pkg/{oms,oss,links,actions,index,automate,ai}, test/{northwind,chinook,e2e,fixtures,integration} would need new stubs. Instead add a narrow interface in the same package (e.g. `ComputedPropertyStore`) and expose CRUD directly on `*PGRepository`.
- TTL-cache tests: inject a clock via `SetNowFunc(func() time.Time)` + an advance helper. Matches `oms.CachedRepository.nowFunc` convention and keeps time-based tests deterministic without calling `time.Sleep`.
- JSONB round-trip in pgx: stage through `[]byte` (`var aggJSON []byte` → `json.Unmarshal`). Passing the struct directly to `rows.Scan` will fail.
- Adding a new BaseType: update (1) `allBaseTypes` map + slice in pkg/types/basetype.go, (2) the count + slice in `TestBaseType_AllDefined`, (3) per-language maps in pkg/sdkgen/typemap.go (ts/python/go). Coerce/Validate have catch-all default branches so opaque types need no work there.
- Content-addressed blob storage: hash + write in one pass via `io.MultiWriter(tempFile, sha256.New())`, then CAS under a mutex — `os.Stat` the destination; if present drop the temp and reuse, else `os.MkdirAll` + `os.Rename`. Never hash a second time from disk.
- Path-traversal guard for FS-backed stores: clean the input (`filepath.Clean(filepath.FromSlash(p))`), reject if it starts with `..` or is absolute, then verify `filepath.Abs(resolved)` is under `filepath.Abs(root)+sep`. Single choke point — duplicate nowhere.
- Multipart upload size cap: wrap `r.Body = http.MaxBytesReader(w, r.Body, max)` BEFORE `ParseMultipartForm`, then check `errors.As(err, &maxErr)` against `*http.MaxBytesError` to distinguish "too large" from generic parse errors. The cap applies to the WHOLE request body (parts + boundary + form fields), so set the limit slightly above the per-file budget if you need exact per-file enforcement.
- New global blob-style API endpoints (no {ontology} segment) belong inside the `r.Group(... auth.MiddlewareFull ...)` block in cmd/server/main.go but mount conditionally: `if deps.MediaStore != nil && deps.MediaCatalog != nil { ... }`. Pattern matches attachment / transactions / sqlqueries — degraded mode (no PG) silently skips registration so unit tests on NewFullRouter don't need to wire every dep.
- Catalog stores (oms.MediaAssetStore, oms.ComputedPropertyStore) MUST be served by the uncached `*PGRepository`, not the `oms.CachedRepository` decorator — the cache wraps the metadata Repository interface only. In main.go, capture `pgRepo := oms.NewPGRepository(pool)` BEFORE wrapping so you can hand the bare repo to deps.MediaCatalog / deps.ComputedPropertyStore.
- Web fetch path (`pkg api/client.ts`) is JSON-only — it hard-codes `Content-Type: application/json` and `JSON.stringify(body)`. Anything that needs multipart/binary or upload progress bypasses `request<T>()` and uses XMLHttpRequest (fetch has no standardized upload-progress event). Grab the access token from `useAuthStore.getState().accessToken` and set `Authorization: Bearer <token>` manually; reuse `ApiRequestError` from `api/client.ts` so error shapes stay uniform.
- react-dropzone in jsdom: the hidden file input is exposed via `getInputProps()`. Tests should drop files by `Object.defineProperty(input, 'files', { value: [file] })` + `fireEvent.change(input)` instead of constructing a DataTransfer (jsdom lacks it). Wrap state-changing calls in `act(async () => {...})` so React flushes the dropzone's internal state update.
- Parameterized BaseType additions (Array/Struct/Union): no migration needed. `Property.TypeConfig` is JSONB and `DataTypeJSON` merges unknown keys through, so adding a `Variants []DataType` / similar field on `pkg/types.DataType` is a wire-only change. Only 4 places need editing: (1) new constant + `allBaseTypes` entry, (2) `json:"xxx,omitempty"` DataType field, (3) Coerce+Validate branches, (4) sdkgen typemap (ts/python/go).
- Union-typed values are tagged on the wire. Two accepted shapes: `{__type: "<variant>", value: <v>}` (universal wrapper — coerce emits this form) OR `{__type: "<variant>", ...structFields}` (flattened tagged struct — read path recognizes it via "key count != 2" heuristic). Validate trusts the `__type` hint when present; untagged values are tried variant-by-variant in declared order. Put specific variants first — `fmt.Sprintf`-backed String coerce is greedy.
- Recursive UI components using self-referential data: label each level with a dot-separated path prop ('', '0', '0.1', ...) so aria-labels stay unique and tests can address any depth via `struct field name 0.1` / `data-testid="struct-fields-0.1"`. Root gets its own sentinel testid (e.g. `struct-fields-root`). Validators walk the same tree recursively — keep "this subtree is valid" one function that short-circuits on first bad leaf.

## 2026-04-18 - US-204 Media 上传 API
- Added `pkg/media/handlers.go` (`Handler` struct + `RegisterRoutes`) exposing the three Foundry-style media endpoints:
  - `POST /api/v2/media` — multipart/form-data with required `file` part and optional `realm` form value. Wraps `r.Body` in `http.MaxBytesReader` at `DefaultMaxUploadBytes` (10 MiB) BEFORE calling `ParseMultipartForm`; `errors.As(err, &maxErr)` distinguishes the 10MB cap (returns `MediaUploadTooLarge` 400) from generic multipart parse failure (`InvalidMultipart` 400). On success the bytes are streamed through `Store.Put` (which content-addresses + dedups them) and a row lands in `MediaAssetStore`.
  - `GET /api/v2/media/{rid}` — looks up the row, opens the blob through the path-traversal-guarded `Store.Open`, then writes `Content-Type` + `Content-Length` + `Content-Disposition: attachment; filename="..."; filename*=UTF-8''<percent-encoded>` so browsers across vintages recover the original filename verbatim.
  - `DELETE /api/v2/media/{rid}` — fetches the row first (so we still know `(realm, sha256)` after the row is gone), deletes the catalog row, then calls `CountBySHA256`. Only when the count is zero does it call `Store.DeletePath` to reclaim the physical file. Dedup-safe: deleting one of two rows that share a sha256 leaves the blob in place for the survivor.
- `Handler.SetMaxUploadBytes(n int64)` overrides the cap (used by the too-large test to keep allocations small); `n <= 0` is silently ignored so callers can't accidentally disable it.
- `auth.UserFromContext(r.Context()).ID` populates `MediaAsset.CreatedBy` when present; in dev/no-auth mode it stays empty.
- Wired into `cmd/server/main.go`:
  - New `ServerDeps.MediaStore *media.Store` and `ServerDeps.MediaCatalog oms.MediaAssetStore` fields.
  - `deps.MediaStore = media.NewStore(cfg.DataDir + "/media")` next to the attachment store init (always wired — the FS root survives degraded mode).
  - `deps.MediaCatalog = pgRepo` (the bare `*PGRepository`, captured BEFORE wrapping with `oms.NewCachedRepository` — the metadata cache decorator does not wrap MediaAssetStore methods).
  - Inside the auth-protected route group, mounted next to attachments, gated on `deps.MediaStore != nil && deps.MediaCatalog != nil` so degraded-mode test routers silently skip registration.

  - Upload happy path: rid prefix, filename / size / mime / default realm "main", catalog row matches, blob present on disk.
  - Custom realm via form field; invalid realm (`"../escape"`) rejected as 400.
  - Missing `file` field → 400 `MissingFile`.
  - Too-large body (cap shrunk to 64 bytes) → 400 `MediaUploadTooLarge`.
  - `DefaultMaxUploadBytes` is exactly 10 MiB.
  - Download happy path: bytes round-trip, `Content-Type` matches, `Content-Disposition` carries `attachment` + filename.
  - Download / delete on unknown rid → 404 `MediaAssetNotFound`.
  - Delete-last-reference: blob reclaimed from disk after row is the final reference.

  - `cmd/server/main.go` (import `pkg/media`, ServerDeps additions, init in main(), conditional route registration)
  - `prd.json` (US-204 passes=true)
- **Learnings for future iterations:**
  - `http.MaxBytesReader` wraps the WHOLE request body — multipart boundaries + form fields count against the cap. If you need exact per-file enforcement, set the limit slightly above the per-file budget OR check `header.Size` after `FormFile` and reject early.
  - `*http.MaxBytesError` is the typed error to look for via `errors.As`; checking `err == io.EOF` or string matching is fragile because Go wraps the error differently across multipart parse vs. body read paths. Both Upload paths (the ParseMultipartForm call AND the streaming Put when the part exceeds the budget) need the same `errors.As` check.
  - When you fetch a row to compute "does the underlying blob still have references after delete", do the GET BEFORE the DELETE — once the row is gone the (realm, sha256) tuple is unrecoverable. The handler order is: Get → Delete row → CountBySHA256 → maybe DeletePath.
  - `oms.CachedRepository` only wraps the metadata `Repository` interface. New narrow stores added on `*PGRepository` (MediaAssetStore, ComputedPropertyStore, etc.) bypass the cache — capture the bare `pgRepo` reference in main.go BEFORE wrapping if you need to hand it to a non-Repository dep.
  - For the multipart test fixture, the exact `Content-Disposition` shape that go-chi/Go's mime/multipart parses correctly is `form-data; name="file"; filename="x.txt"` — `WriteField` won't set per-part headers, so use `mw.CreatePart` with an explicit textproto.MIMEHeader-like map.

  - `api/client.ts::request<T>()` is JSON-only (hard-codes stringify).   - `dev-browser` skill isn't registered in this harness; the PRD "verify in browser" line is covered by the unit/integration tests here + manual QA. Flag this in the PR so reviewers run the dev server once (`make dev`) and confirm drag-and-drop against a Media-typed property.

## 2026-04-18 - US-206 Union Types 支持
- Added `Union` as BaseType #23 (`types.Union = "union"`); bumped `allBaseTypes` + `TestBaseType_AllDefined` count to 23. Also exported two well-known keys: `UnionDiscriminatorKey = "__type"` and `UnionValueKey = "value"` so downstream serializers agree on the wire shape.
- Extended `DataType` with `Variants []DataType` (JSON `variants`, `omitempty`). No new DB column — `Property.TypeConfig` is already JSONB, so `{"variants": [...]}` rides along with existing persistence. Schema round-trips via the existing `DataTypeJSON` path.
- Validate: new `validateUnion` branch. If the value is a map carrying `__type`, it is routed directly to the named variant (error if no variant matches that discriminator). Otherwise variants are tried in declared order; first match wins. Empty variants list is an error. Nullable honors `nullable` at the dispatcher level.
- Coerce: new `coerceUnion` branch. If input is tagged, the inner value is coerced against that variant only. Untagged input is attempted against each variant in declared order — Coerce + Validate must both succeed — and the first success is wrapped as `{"__type": "<variant>", "value": <coerced>}`. Nil input passes through unchanged.
- Added `unwrapUnionValue` shared by Validate/Coerce. Supports both wire shapes: the universal wrapper `{__type, value}` (exactly 2 keys → scalar-style unwrap) and the flattened tagged-struct shape `{__type, ...structFields}` (any other key count → struct-style, strip `__type` and pass the rest through).
- sdkgen/typemap.go: Union → `unknown` (ts), `Any` (python), `interface{}` (go) — the one escape hatch for generated types when the concrete variant is not known at codegen time.
- 15 new unit tests in `pkg/types/union_test.go`: BaseType included + wire value, schema JSON round-trip with Variants, validate-first-variant, validate-later-variant, no-variant-match, empty-variants, nil+nullable, discriminator routes to struct variant, discriminator-unknown-variant, discriminator-mismatched-inner-value, wrapped-value-matches, coerce-first-variant-wins, coerce-falls-through-on-first-failure, coerce-honors-hint (coerces 42 → "42" under `__type=string`), empty-variants coerce error, nil pass-through.
- Files changed:
  - `pkg/types/basetype.go` (Union constant, allBaseTypes entry, UnionDiscriminatorKey/UnionValueKey exports, Variants field on DataType)
  - `pkg/types/basetype_test.go` (bumped count to 23, added Union to slice)
  - `pkg/types/validate.go` (Union branch + validateUnion + unwrapUnionValue)
  - `pkg/types/coerce.go` (Union branch + coerceUnion + wrapUnionValue helper)
  - `pkg/types/union_test.go` (new, 15 tests)
  - `pkg/sdkgen/typemap.go` (Union entries for ts/python/go)
  - `prd.json` (US-206 passes=true)
- **Learnings for future iterations:**
  - `DataType` was designed to be extensible via JSON fields (SubType, Fields, Precision, Scale, now Variants). Adding a new parameterized type only needs: (1) a new BaseType constant + allBaseTypes entry, (2) a new `json:"xxx,omitempty"` field on DataType, (3) branches in Coerce + Validate, (4) sdkgen typemap — NO migration required, because `Property.TypeConfig` is JSONB and `DataTypeJSON` already merges unknown keys through.
  - The `{__type, value}` wrapper is the cleanest universal shape for tagged unions because it works for both scalars and structs. The flattened form `{__type, ...fields}` still gets recognized (via the "any key count other than exactly 2" heuristic in `unwrapUnionValue`) so callers that want idiomatic tagged-struct JSON don't need to wrap into a nested `value`. Both are supported on read; write path produces the wrapper form for consistency.
  - When Coerce tries each variant, both Coerce AND Validate must succeed for the variant to be accepted. Coerce alone is too lenient for `Union[string, integer]` — `coerceString(42)` succeeds via `fmt.Sprintf`, which would mean integer input always lands in the first variant if it's string. The Validate pass after Coerce is what makes the "try-in-order" semantic meaningful.
  - Ordering matters: put MORE-specific variants first. For `Union[Integer, String]`, `"42"` coerces to Integer; `"hello"` falls through to String. Reversing the order would route `"42"` to String (via fmt.Sprintf) and never try Integer.
  - `TestBaseType_AllDefined` is the canary that flags any new BaseType addition — the fixed-length slice + count assertion catches drift between `allBaseTypes` and the explicit enumeration.

- **Learnings for future iterations:**
  - Recursive React components that need to be addressable by tests at any depth should accept a `path?: string` prop (default `""` for root) and embed it in both `data-testid` and every `aria-label` they emit. Labels like `struct field name 0.1.2` stay unique; a parent test that scopes via `within(getByTestId('struct-fields-0.1'))` stays tidy. Don't use raw integer indices at nested levels — they collide with the parent's.
  - When broadening a choice set in the UI (here: allowing 'struct' in the nested type select), the validator must ALSO broaden. If `isStructTreeValid` only checked the top-level, an empty nested struct would silently ship a `{fields: []}` subtree to the backend. The rule "allowed in the UI ⇒ validated in the UI" is easy to forget because the scalar validator already short-circuits on the top-level length==0 check.
  - React Testing Library accessible-name matching on buttons with decorative prefixes: "+ Add field" matches `/Add field/i` but NOT `/^Add field$/i`. Anchored regexes are dangerous when labels carry icons / punctuation. Prefer substring matches + scoping via `within(parentEl)` to disambiguate rather than anchoring.
  - Keep wire serialization centralized in one helper (`serializeStructFields`). The in-memory state can carry an `undefined` or an empty `fields` on scalar rows while the user is editing, but the JSON that hits the backend must be canonical — one function at the boundary is the only way to keep that invariant. Same idea as pkg/oss/objectset's validate-at-boundary pattern.
