- Implementation:
  - Updated `web/src/lib/serviceWorker.ts` to import `replayQueue` in the existing static `offlineRequestQueue` import and removed the dynamic import from `replayOnce`.
  - Kept replay coalescing and `executeQueuedEntry` behavior unchanged.
- Verification evidence:

- Selected as the next highest-priority incomplete story after SELF-410.
- Root cause:
  - With web dependencies installed, `go list ./... | rg "node_modules|flatted"` emitted `github.com/liyang/weave/web/node_modules/flatted/golang/pkg/flatted`.
  - The local `Makefile` `test-unit` target and CI Go build/vet/test steps used raw `./...` package patterns, so local package discovery could include installed web dependency trees.
- TDD red:
  - Added `TestBDD_GoPackageListExcludesWebDependencyTrees` in `scripts/ci/ci_workflow_bdd_test.go`.
  - `go test ./scripts/ci -run TestBDD_GoPackageListExcludesWebDependencyTrees -count=1 -v`: failed for the expected reason because `scripts/ci/go-packages.sh` did not exist.
  - After wiring the first helper into CI build, verification exposed a second issue: an explicit test package list includes test-only packages that `go build` cannot build. Added a red assertion for `scripts/ci/go-packages.sh --build`; it failed because the helper still returned `github.com/liyang/weave/scripts/ci`.
- Implementation:
  - Added executable `scripts/ci/go-packages.sh`.
  - Default mode uses `go list -e ./...` and filters `node_modules` package paths so test/vet package lists stay scoped to Weave packages.
  - `--build` mode uses Go package metadata to return only packages with buildable non-test Go files, while applying the same `node_modules` filter.
  - Updated `Makefile` `test-unit`, CI Build/Vet/Test steps, and `scripts/ci/govulncheck.sh` to use the shared helper.
