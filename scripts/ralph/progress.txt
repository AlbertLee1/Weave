## Codebase Patterns
- Backend write surfaces that need ambiguous-body hardening should switch from `json.NewDecoder(r.Body).Decode(&req)` to `httputil.ReadJSON(r, &req)` so the single-JSON-value contract is enforced and trailing tokens are rejected at the API boundary.
- BDD-style integration tests for ambiguous JSON bodies pair (a) a concatenated-body request asserting 400 + `single JSON value` reason + no state mutation with (b) a well-formed body regression asserting the existing happy path still works.
- Auth handler tests use `withAdmin(req)` (defined in `pkg/auth/api_key_handlers_test.go`) to attach an admin `*User` to the request context so `UserFromContext` resolves.
- Naming convention for ambiguous-body BDD tests in this repo: `TestBDD_<Surface>RejectsAmbiguousJSONBody_<StoryID>` or `TestBDD_HandlerRejectsAmbiguousJSONBodies_<StoryID>`.
- After P2A-303, the role/group/service-account admin write handlers in `pkg/auth/` all decode through `httputil.ReadJSON`. Remaining `json.NewDecoder(r.Body)` call sites in `pkg/auth/` (api_key, user_role, mfa, marking, refresh, logout) are candidates for the next ambiguous-body audit — `grep -nR 'json.NewDecoder(r.Body)' pkg/auth/` enumerates them.
