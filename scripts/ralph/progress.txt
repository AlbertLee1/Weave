## Codebase Patterns
- 每个前端 story 是一个独立纯逻辑模块：`web/src/features/vertex/<feature>/<name>.ts` + `<name>.test.ts`，不依赖 React，让 vitest 在 happy-dom 之外直接驱动。
- 测试命名沿用 BDD：`describe('VTX-### <feature>')` + `it('given_<State>_when_<Action>_then_<Outcome>')`；时间常量用 `new Date(...).getTime()` 写绝对时间戳，可读且稳定。
- compare windows 已在 VTX-079 (`web/src/features/vertex/timeSeries/compareWindows.ts`) 提供，新 story 直接复用，不要重复实现。
- vitest 配置已支持 `vi.useFakeTimers()`，定时器/防抖类 helper 用假时钟测试。
- 项目根目录 `tsconfig` 有 `erasableSyntaxOnly`，预先存在的两处错误 (`sdk/typescript/src/vertex.ts`、`src/vertex/SdkVertexClient.test.ts`) 与本 stream 无关。
- uPlot 类型用 `import type uPlotCtor from 'uplot'`，options 写 `uPlotCtor.Options`（沿用 `MultiSeriesChart` / `TimeSeriesChart` 现有模式）。注意 `select` 配置如果只写 `{ show: false }` 会 TS2739（必须给 left/top/width/height），干脆省略 `select`，默认就是禁用。

- **Learnings for future iterations:**
  - BDD spec 给的 URL 路径形式（`/quiver/{objectRid}/{property}`）与现有 React Router 路由（`/quiver/:ontology/:rid`，rid 是 dashboard rid）冲突，不能直译。采用 query param 形式 `/quiver/{ontology}?objectRid=...&property=...&objectType=...&primaryKey=...`，让 QuiverPage 接 `useSearchParams` 在 mount 时 prefill 一个 SeriesSpec，等价语义但保留现有路由不变。这种 spec-vs-codebase 冲突优先选 query param 而不是加新路由 — 改 routing 是更大 blast radius，应由专门 routing story 决定。

  - setCaseStudy 同 rid no-op-on-dependent-state 的设计：避免用户重命名 Case Study 时把已加载的 Scenarios/Rows 清空。但传入的对象引用是新的（caseStudy 字段更新），React 层用 `useMemo` 依赖 `state.caseStudy.rid` 而不是 `state.caseStudy` 引用，否则会触发不必要重渲。
  - "Run" 按钮的精细禁用规则（需要 ≥1 scenario，且任何 scenario.immutable=false 等）不在 `getToolbarButtons` 里判断 — 该 helper 只回答"是否暴露按钮"，"按钮是否可点"留给 React 层组合 `state.scenarios.length` / `scenarios.some(s => !s.immutable)`。避免 helper 膨胀为业务规则枢纽。
  - Row 类型用 discriminated union（`kind: 'model'|'action'`）而不是两个独立数组，`state.rows` 单列存储是为了未来插入顺序（"先加 M1，再加 A1，再加 M2" 用户可能希望按时间顺序看到混排），`getRowGroups` 才在派生时分组。如果 spec 之后要求"Models 永远在 Actions 上面"，改 `getRowGroups` 不动 state 即可。
  - immutable scenario 的视觉差异（灰色列头 / 锁图标）由 React 层根据 `scenario.immutable` 自行装饰，本模块的 `getColumnHeaders` 只回 name 字面值；VTX-037 的"Scenario is immutable. Duplicate to modify."提示走同样路径。
  - dev-browser skill 不可用 — TanStack Table 接线 + + Add Case Study 对话框浏览器验证留到 React 组件接线 story。

- **Learnings for future iterations:**
  - 对话框 reducer 选择"open/close 不读 prior state"的设计：之前我考虑过传入 prior state 让 reducer 决定，但 ESLint flat config 不识别 `_state` 这种 leading-underscore 约定（项目 `eslint.config.js` 没配 `argsIgnorePattern`），unused-vars 会硬性报错；同时打开对话框语义上确实不依赖 prior state（永远 reset），所以索性去掉参数。Scenario 版的 `caseStudyRid` 因为是必需信息保留入参。这与 sibling `scenarioPane.ts` 的 `togglePane(state)` 风格略不同 —— 那些 reducer 真的读 prior state（toggle / set 都依赖当前值），不是参数约定的差异。
