## Codebase Patterns
- LinkType admin handlers use **tri-state pointer** for partial PUT fields (nil = preserve, &value = set). Mirror this for any new optional field; bare value collapses "omit" and "clear" into one (see UpdateLinkTypeRequest.PropagateMarkings & TypeClasses).
- LinkType wire format uses `omitempty` so the JSON shape stays backwards compatible — emit new fields from ToWireJSON only when non-zero.
- PostgreSQL TEXT[] columns: pgx v5 scans into `[]string` directly. SELECT with `COALESCE(col, '{}'::text[])` keeps nil rows safe; INSERT pass `[]string{}` (not nil) to avoid pgx encoding gotchas.
- Frontend Vertex pure helpers live under `web/src/features/vertex/<feature>/` with `<helper>.ts` + `<helper>.test.ts` siblings (Vitest, no React).
- Frontend admin UI for OMS resources lives in `web/src/components/admin/*.tsx`; co-located `__tests__/*.test.tsx` use a `installFetch(state)` stub pattern to mock the v2 REST endpoints.
- `cmd/server/embed.go` requires `cmd/server/web/dist/*` to exist before `go build ./...` works — keep a placeholder file when running Go tests without first building the frontend.
- Migration numbering: VTX stream uses 000200+. Add a `down.sql` even if it just drops the column.
- **JSON Schema validation**: use `github.com/santhosh-tekuri/jsonschema/v5` (already in go.mod). Embed the schema with `//go:embed`, register via `compiler.AddResource(memURL, strings.NewReader(...))`, set `compiler.Draft = jsonschema.Draft7`, then `Compile(memURL)`. Pattern is established in `pkg/actions/parameter_schema.go`.
- **OMS reference checks** belong on a tiny purpose-built interface (e.g. `ReferenceLookup{ GetObjectType, GetLinkType }`) that `*oms.PGRepository` satisfies structurally. Don't import `oms.Repository` (huge surface) into a downstream package — the focused interface keeps tests cheap.
- Pre-existing baseline failures unrelated to your story: `cmd/server.TestContract_AllRoutesDocumented` (missing OpenAPI entry for `/timeseries/{property}` from VTX-030) + perf gates `pkg/cellsec.TestUS376_PerfGate_*` and `pkg/security.TestRLSEvaluator_PerformanceGate`. Don't try to fix these in your iteration — verify with `git stash` if in doubt.
- `prd.json` and `progress.txt` at repo root are symlinks to `scripts/ralph/{prd.json,progress.txt}` — Edit through the symlink fails ("Refusing to write through symlink"); always edit the real path.
- **New vertex routes**: every chi route under `/api/vertex/...` must be either in `api/openapi.yaml` or in `cmd/server/contract_test.go::undocumentedRouteAllowList`, otherwise `TestContract_AllRoutesDocumented` fails. VTX-009 routes ride the allow-list until the OpenAPI schemas land.
- **Auth in handler tests**: chi-router-only tests can stash an auth.User into the request context via `req.WithContext(auth.WithUser(req.Context(), &auth.User{ID: ...}))`. No middleware required. The handler reads via `auth.UserFromContext(r.Context())` which returns nil for anonymous calls; ACL checks should fall through to "public" only when both the user is nil AND the resource opts in (e.g. empty CreatedBy) so legacy fixtures keep working.
- **HTTP 410 Gone**: there was no constructor for 410 in `pkg/apierror`. Added `NewGone(name, params)` emitting errorCode NOT_FOUND with statusCode 410. Use it when distinguishing "never existed" (404) from "deliberately revoked" (410) — share links, tombstoned resources, etc.
- **There is an orphan `pkg/vertex/sharelinks` package** with pure helpers (`EvaluateAccess`, `MaskGraphPayload`, `GenerateToken`) that pre-dates VTX-009's `layers[]` payload shape — it operates on `nodes[]` and uses `•••` as the mask token. Do NOT consume it for new VTX work; the BDD wants ASCII `***` masking on `layers[*].properties`. The graphsvc `maskLayerPropertyValues` helper is the canonical one.
- **IDOR guard on "override target" endpoints**: when a Save / Copy / Move action accepts a `overrideXxxRid` (or similar) field, enforce ACL on the **target** rid, not the source path rid. Otherwise a caller with read on A can mutate B by routing through A. See `pkg/vertex/graphsvc/handler.go::saveWidget` for the canonical example.
- **Compact / projected payload variants**: express as a pure `<base>CompactPayload(raw json.RawMessage)` projection + thin handler that runs the projection on the existing repo.Get path. Reuses ACL / error / shape logic; the projection function falls through to the original bytes on decode failure so opaque fixtures still flow.
- **Admin-only PUT endpoints**: inline the role check in the handler with `isAdmin(auth.UserFromContext(r.Context()))` returning 403 PERMISSION_DENIED. Nil user (anonymous) is never admin — collapse "missing user" into "not authorized" so the surface keeps mirroring the rest of the vertex namespace (which tolerates anonymous reads for legacy fixtures, but never anonymous writes).
- **Singleton config tables**: `id INTEGER PRIMARY KEY CHECK (id = 1)` + `INSERT ... ON CONFLICT (id) DO UPDATE` is the project idiom for one-row admin-knob tables. Read returns `pgx.ErrNoRows` on a fresh installation; the store maps that to DefaultConfig so the bootstrap state and the post-PUT state share the same Get-shape.
- **Partial-update PUT bodies**: declare the request struct with `*<T>` pointer fields so `nil` means "field omitted" and `&zero` means "explicitly set to zero". The handler merges the request onto a freshly-read current Config, then writes the merged value back through Set — no separate "patch" code path.
- **Phase-aligned E2E smokes** belong in `test/e2e/vertex/` as a single BDD-shaped function under `package vertex_test`. Wire the in-memory `Repo` / `TemplateStore` / `ShareLinkStore` + `chi.Router` + `Handler.RegisterRoutes` — same shape as cmd/server.main in degraded-mode boots; no PG, no Bleve, no NATS unless the lifecycle actually touches them. Assert at every step in one function so the wall-clock budget (`time.Since(start) ≤ budget`) covers the full chain — subtests would split the timer.

  - Gotcha: Reused error names matter. `GraphWriteForbidden` is a fresh ErrorName (vs `GraphReadForbidden` for the read ACL). Keep the read/write distinction explicit so the SDK can surface different copy ("Read-only graph" vs "You don't own this graph") downstream.
  - Useful: The VTX-009 graph endpoints define a single ACL helper (`canReadGraph`); for VTX-014 the natural choice was to re-use it (rather than introduce a separate `canWriteGraph`) since the project's RBAC is still owner-or-admin at this layer. When real project-level RBAC lands, splitting the two will be a one-line edit at the call sites.
