## RLLM-001 - Harden MCP Resource List Pagination
Status: PASS

### Root Cause
- Investigation target: `pkg/mcp/resources.go` currently accepts any non-negative `pageSize` from request params or decoded cursors.
- Failure path: with a valid cursor whose `afterUri` sorts before a real resource, `start` becomes non-zero; then `start + params.PageSize` can overflow for `math.MaxInt`, leading to unsafe slice bounds.

### Red
- Added `TestBDD_HTTPTransportResourcesListRejectsUnsafePageSizeCursor_RLLM001` for the public MCP HTTP transport with a valid-looking cursor and `pageSize=MaxInt`.
- Added `TestResourcesList_GivenCursorWithUnsafeDecodedPageSize_WhenListThenInvalidParams_RLLM001` for decoded cursor page-size validation.
- Command: `go test ./pkg/mcp -run 'TestBDD_HTTPTransportResourcesListRejectsUnsafePageSizeCursor_RLLM001|TestResourcesList_GivenCursorWithUnsafeDecodedPageSize_WhenListThenInvalidParams_RLLM001' -count=1 -v`
- Result: failed as expected with `panic: runtime error: index out of range [9223372036854775807] with length 1` from `pkg/mcp/resources.go:205`.

### Green
- Added `maxResourcePageSize = 500` and reject request `pageSize` values above that cap with JSON-RPC `CodeInvalidParams`.
- Applied the same cap to decoded cursor `pageSize` values so tampered opaque cursors cannot carry unsafe pagination state.
- Replaced `start + params.PageSize >= len(resources)` with `remaining := len(resources) - start` and `params.PageSize >= remaining`, so safe page sizes larger than the remaining catalog return the final page without overflow-prone arithmetic.
- Added `TestResourcesList_GivenCursorNearEndAndSafeLargePageSize_WhenListThenReturnsFinalPage_RLLM001` to lock the safe final-page behavior.

### Reusable Learning
- MCP resource-list cursors are opaque to clients but still attacker-controlled at the protocol boundary; validate decoded cursor fields with the same policy as request params.
- Pagination arithmetic should compare requested size against `remaining := len(items) - start` before computing `end`, not add untrusted size to `start` inside the bounds check.

## Codebase Patterns
