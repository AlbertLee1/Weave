## SELF-410 - Quiet offline replay Web build warning
- Selected because local CI was green but `npm --prefix web run build` emitted a deterministic Vite warning:
  - `web/src/lib/offlineRequestQueue.ts is dynamically imported by web/src/lib/serviceWorker.ts but also statically imported by web/src/lib/queuedRequest.ts, web/src/lib/serviceWorker.ts, web/src/main.tsx`.
- Root cause:
  - `serviceWorker.ts` statically imported `startAutoReplay` from `offlineRequestQueue.ts` and also lazy-imported `replayQueue` from the same module inside `replayOnce`.
  - Vite cannot split a module that is already statically in the graph, so the lazy import produced a production-build warning without providing chunking value.
- TDD red:
  - Added `web/src/lib/__tests__/serviceWorkerChunking.bdd.test.ts`.
  - First harness attempt failed for the wrong reason because Vitest's `import.meta.url` was not a file URL; corrected the test to use Vite's `?raw` source import so it works under the web tsconfig.
  - `npm --prefix web test -- --run src/lib/__tests__/serviceWorkerChunking.bdd.test.ts`: failed for the expected reason, asserting that `serviceWorker.ts` still contained `import('./offlineRequestQueue')`.
- Implementation:
  - Updated `web/src/lib/serviceWorker.ts` to import `replayQueue` in the existing static `offlineRequestQueue` import and removed the dynamic import from `replayOnce`.
  - Kept replay coalescing and `executeQueuedEntry` behavior unchanged.
