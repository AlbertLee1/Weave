## Codebase Patterns
- **Ambiguous-JSON hardening recipe**: when an admin write surface uses `json.NewDecoder(r.Body).Decode(&req)`, swap it for `httputil.ReadJSON(r, &req)`. ReadJSON additionally calls `dec.Decode(&extra)` and requires the result to be `io.EOF`, so concatenated/trailing JSON is rejected with `"request body must contain a single JSON value"`. The handler's existing `apierror.NewInvalidParameter("Invalid…", {"reason": err.Error()})` already surfaces that phrase to clients.
- **Empty-body endpoints (e.g. POST .../rotate)**: keep the `if r.Body != nil && r.ContentLength != 0` outer guard around `httputil.ReadJSON` — ReadJSON returns `io.EOF` on empty bodies, which the rotate flow needs to treat as "use defaults". Existing well-formed and empty-body sub-tests must stay green even when the ambiguous-body sub-test is red.
- **BDD shape for P2A-30x hardening**: integration tests live next to handlers as `*_handlers_bdd_test.go` and (a) seed an in-memory repo, (b) send a concatenated body, (c) assert via `assertSingleJSONValueRejection` (defined in `pkg/auth/role_handlers_bdd_test.go`) that the response is 400 with the expected errorName + a reason containing "single JSON value", (d) snapshot repo state before/after to prove the rejected request was non-mutating, and (e) include a "well-formed bodies still succeed" sub-test as a regression guard. Reuse `withAdmin` / `withViewer` from `pkg/auth/api_key_handlers_test.go`.
- **fakeAPIKeyRepo lives in `pkg/auth/middleware_test.go`** — BDD tests in pkg/auth that need to seed/inspect API keys can reuse it via `newFakeAPIKeyRepo()` and `newAPIKeyHandlerHarness(t)`.

## [2026-05-23 16:18] - P2A-304
- Hardened POST /api/admin/api-keys (Create) and POST /api/admin/api-keys/{id}/rotate (Rotate) to reject ambiguous JSON request bodies. Both routes previously used the standard `json.NewDecoder(r.Body).Decode(&req)`, which silently dropped trailing bytes after the first decoded value; an attacker who could influence one of these admin requests could append `{"name":"smuggled"}` to a legitimate body and have the trailing object ignored (creating only the first key) or, worse, future API surfaces could route on the smuggled trailer. The fix routes both handlers through `httputil.ReadJSON`, which uses `dec.Decode(&extra) == io.EOF` to enforce a single JSON value.
