## Codebase Patterns
- 后端 BDD 入口：`make test-bdd` → `go test -tags bdd -count=1 -v ./test/bdd/...`。
  `bdd` 构建标签让套件不污染默认 `go test ./...` / `make test-unit`。
- 复用 `internal/testutil.StartPGContainer(t)` + `database.RunMigrationsUp(dsn, testutil.MigrationsDir())`
  是后端 PG 真实容器测试的标准入口；godog 步骤通过它拿到 `*pgxpool.Pool` 与 `*oms.PGRepository`。
- godog v0.15.1 API：`godog.TestSuite{ScenarioInitializer: ..., Options: &godog.Options{Format: "pretty",
  Paths: []string{"features"}, TestingT: t}}`；步骤注册用 `sc.Given/When/Then(regex, fn)`。
- 不要把 `*testing.T` 在多 scenario 共享时假设为同一个 — godog 给每个 scenario 走 subtest，
  且 `ScenarioInitializer` 每个 scenario 调一次，所以 per-scenario state（含容器句柄）独立。
- `pkg/oms.Repository` 当前没有 `DeleteOntology`；BDD/集成场景要硬删除时直接走 `pool.Exec` 即可，
  但请同时校验 FK（snapshots/branches）级联前确认。
- 前端 BDD 入口：`cd web && npx playwright test --grep @smoke`（或跑 `tests/` 子集）。
  Playwright 单 config 同时覆盖两套：`web/e2e/`（已有命令式 spec）与 `web/tests/`（新 BDD）。
- `web/tests/support/` 是前端 BDD 共享底座：`bdd.ts`（Given/When/Then + describeFeature）、
  `signIn.ts`（AUTH_MODE-aware）、`seedOntology.ts`（reuse-or-create）、`dataFactory.ts`（uniqueName +
  payload builders）、`pageObjects/*Page.ts`（封装 data-testid，禁止 spec 直接拼 testid）。
- BDD spec 命名 `feature.<domain>.<scenario>.spec.ts`，scenario 标题以 `Scenario:` 开头，标签用 `@smoke`/`@regression`。
- Playwright `testDir: '.'` + `testMatch: /(?:e2e|tests)\/.*\.spec\.ts$/` 比 glob 数组更稳；务必加 `testIgnore: ['src/**', 'node_modules/**', 'dist/**', 'coverage/**', 'playwright-report/**']`，否则会扫到 `src/**/*.test.ts` 的 vitest 测试导致诡异 `test.describe not expected here`。
- `npx playwright test` 必须从 `web/` 目录跑，否则会落到仓库根、用默认 testMatch 扫到 `examples/ts-quickstart/.../__tests__/*.test.ts`（用 `node:test`）误执行。Bash 工具会把 cwd 重置到仓库根，所以脚本里要 `cd /Users/liyang/Documents/Community/Weave/web && npx playwright test ...`。
- `make e2e-up` 的 seed 步骤遇 FK 阻塞（functions → ontologies）会失败但 weave/vite 已起来；可手动 `docker exec weave-postgres-1 psql -U weave -d weave -c "DELETE FROM functions WHERE ontology_rid='ri.ontology.main.ontology.northwind';"` 再 `make e2e-seed` 恢复。

- **Learnings for future iterations:**
  - Bash 工具会把 cwd 重置到仓库根；Playwright 必须 `cd web && npx playwright ...`，否则 npx 会按默认 testMatch 扫到 `examples/ts-quickstart/src/__tests__/*.test.ts`（用 `node:test`）一起跑，搞出 `Cannot redefine property: Symbol($$jest-matchers-object)` + `test.describe not expected here` 这种诡异组合。
  - `web/vite.config.ts` 同时包含 `test:` 段（vitest 配置）；vitest 的 `exclude` 列了 `**/e2e/**` 但**不含** `**/tests/**`。如果你给 `web/tests/**/*.spec.ts` 用了 `.test.ts` 或 vitest 也跑得到的命名，会和 Playwright 互踩 — 所以约定 BDD spec 只用 `*.spec.ts` 且文件名以 `feature.` 开头是有意义的隔离。

  - `make e2e-up` 在 OS 升级后第一次跑会因为容器全部重建而 seed 阶段被旧 `functions` 行卡住（seed 走 wipe-and-reseed，但 ontologies 上有 functions FK）。流程是先 `docker compose up -d --wait postgres nats` 再 `make e2e-up`，遇到 FK 阻塞就 `docker exec weave-postgres-1 psql -U weave -d weave -c "DELETE FROM functions WHERE ontology_rid LIKE 'ri.ontology.main.ontology.northwind%';"` 后 `make e2e-seed`。
