## Codebase Patterns
- Saved Browser views are owned by `web/src/components/browser/SavedSearchesPanel.tsx`. The `onLoad` callback receives the whole `SavedSearch` row (not just the definition) so the parent BrowserPage can track which saved entry is currently applied. When you mutate any saved-definition input (searchText, filters, facets, sort, viewMode) you MUST also clear `activeSavedSearchId` in BrowserPage so the Active indicator stays truthful.
- The BrowserPage view-mode toolbar must call `handleViewModeChange(mode)` (not `setViewMode(mode)` directly) so user-driven mode switches clear the active-saved-search indicator. The saved-search loader sets `setViewMode` directly so the indicator survives the load.
- BDD tests for the Browser saved-search active indicator live in `web/src/components/browser/__tests__/BrowserPage.savedSearches.bdd.test.tsx` and rely on `aria-current="true"` + `saved-search-active-badge-{id}` test ids.
