## Codebase Patterns
- Use `httputil.ReadJSON(r, &req)` for Go HTTP handlers that accept JSON request bodies and must reject concatenated/trailing JSON values at the API boundary.
- Frontend BDD tests use `*.bdd.test.tsx` under the owning component's `__tests__` folder.
- BrowserPage search request behavior is covered in `web/src/components/browser/__tests__/BrowserPage.search.bdd.test.tsx` with MSW and captured POST bodies.
- Browser search highlights are documented in OpenAPI as `SearchObjectsRequest.highlight` and returned on rows as `_highlights: { field: [snippet...] }`.
- Render API highlight snippets by parsing only the backend's `<mark>` / `</mark>` delimiters into React elements; leave all other snippet text as text nodes instead of using `dangerouslySetInnerHTML`.
- Browser facet fields should prefer detailed `Property[]` metadata once available because it carries `isSearchable`, `isArray`, and `baseType`; compact `objectType.properties` remains the fallback while detailed metadata is loading or unavailable.
- Saved Browser view definitions are frontend-owned opaque JSON; adding presentation state is a type-only frontend contract change and does not require a backend API change.
- BrowserPage should validate saved presentation mode values before applying them and should treat missing `viewMode` as the table fallback for legacy saved definitions.
- CI contract BDD tests live in `scripts/ci/ci_workflow_bdd_test.go` and should guard workflow/tooling expectations that are easy to miss in local verifier subsets.
- Security-gate dependency repairs should add a small CI BDD guard for the fixed module floor so the same vulnerability class does not silently regress.
