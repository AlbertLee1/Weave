## Codebase Patterns
- Scheduler loops expose Start/Stop lifecycle methods and run an immediate first cycle before ticking on an interval.
- Scheduler goroutines should capture lifecycle channels into locals before entering the select loop; Stop may mutate struct fields under lock while the goroutine is still running.
- Race-enabled tests that observe goroutine-updated fixture state should use atomic or mutex-protected counters.
- Sidebar tests that assert auth-gated admin links must wait for auth-gated UI state; ontology route links can render before `/api/v2/me` resolves and are not proof that admin identity has loaded.

## SELF-301 - Make audit and LDAP schedulers race-clean in Go CI
- Selected as the first story because the latest Go CI failure includes deterministic race detector reports and local targeted red tests reproduce quickly.
- Red: `go test -race ./pkg/audit -run TestRootHashPublisher_Scheduler_RunsImmediateCycle -count=1 -v` failed with races on `chainStoreStub.calls` and `RootHashPublisher.stopCh`.
- Red: `go test -race ./pkg/auth -run TestScheduler_RunsImmediatelyAndStops -count=1 -v` failed with a race on `LDAPSyncScheduler.stopCh`.
- Root cause:
  - `RootHashPublisher.Start` and `LDAPSyncScheduler.Start` selected on `p.stopCh` / `s.stopCh` by reading the struct field from the goroutine.
  - `Stop` wrote the same struct field to nil under lock while the goroutine was still reading it, so the lock did not protect the select-side access.
  - The audit scheduler test also read `chainStoreStub.calls` while the scheduler goroutine incremented it.
- Implementation:
  - Captured each scheduler's `stopCh` and `doneCh` into locals before launching the goroutine.
  - Updated the goroutines to close/select on the captured channels instead of rereading mutable struct fields.
  - Changed `chainStoreStub.calls` to `atomic.Int64` so the immediate-cycle assertion is race-clean.
