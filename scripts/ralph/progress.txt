## Codebase Patterns
- **Ambiguous-JSON hardening recipe (P2A-30x family)**: when an admin write surface uses `json.NewDecoder(r.Body).Decode(&req)`, swap it for `httputil.ReadJSON(r, &req)`. ReadJSON additionally calls `dec.Decode(&extra)` and requires the result to be `io.EOF`, so concatenated/trailing JSON is rejected with `"request body must contain a single JSON value"`. The handler's existing `apierror.NewInvalidParameter("Invalid…", {"reason": err.Error()})` already surfaces that phrase to clients.
- **Empty-body endpoints (e.g. POST .../rotate)**: keep the `if r.Body != nil && r.ContentLength != 0` outer guard around `httputil.ReadJSON` — ReadJSON returns `io.EOF` on empty bodies, which "use defaults" flows must treat as a non-error. Pair with a "no-body request still succeeds" regression sub-test.
- **BDD shape for P2A-30x hardening**: integration tests live next to handlers as `*_handlers_bdd_test.go` and (a) seed an in-memory repo via the existing harness (`newRoleHandlerHarness`, `newUserRoleHandlerHarness`, `newAPIKeyHandlerHarness(t)`, …), (b) send a concatenated body, (c) assert via `assertSingleJSONValueRejection` (in `pkg/auth/role_handlers_bdd_test.go`) that the response is 400 with the expected errorName + a reason containing "single JSON value", (d) snapshot repo state before/after to prove the rejected request was non-mutating, and (e) include a "well-formed body still succeeds" sub-test as a regression guard.
- **Shared test harnesses**: `withAdmin` / `withViewer` from `pkg/auth/api_key_handlers_test.go` are reusable across all `pkg/auth` BDD tests. `fakeUserRepo` (in `pkg/auth/role_resolver_test.go`) implements both `UserRepository` and `UserRoleRevoker`; reuse via `newFakeUserRepo()` and `newUserRoleHandlerHarness()` rather than re-rolling.
- **fakeRoleRepo seeds built-ins**: `newFakeRoleRepo()` pre-seeds RoleViewer/RoleEditor/RoleOntologyOwner/RoleAdmin/RoleIngestWriter so role-existence checks pass without extra setup — handy when the test only cares about the request-decoding surface, not role registration.

## [2026-05-24 08:50] - P2A-305
- Hardened POST /api/admin/users/{userId}/roles (UserRoleHandler.GrantRole) to reject ambiguous JSON request bodies. Before this commit the handler called `json.NewDecoder(r.Body).Decode(&req)`, so a concatenated payload like `{"role":"viewer"}{"role":"admin"}` decoded only the first object and silently dropped the trailing role. The trailer is invisible to the audit log (which records `req.Role` only after decode) but visible to anything that re-parses the raw bytes (proxies, WAFs, log scrapers), giving an attacker who can influence the request body a path to confuse downstream observers about which role grant actually landed. The fix routes the handler through `httputil.ReadJSON`, which uses `dec.Decode(&extra) == io.EOF` to enforce the single-JSON-value contract that P2A-301..304 already imposed on the rest of the auth admin surface.

## Codebase Patterns
- `web/src/api/client.ts` throws `ApiRequestError` whose `.message` is `${errorCode}: ${errorName}` — never surface that string to operators. Inspect `err.errorName` (e.g. `SavedSearchNameConflict`) and translate to a friendly inline message; only fall back to `err.message` for truly unknown errors.
- Backend uniqueness on saved searches is `(createdBy, trimmed name)` exact match — case- AND whitespace-sensitive (see `pkg/savedsearches/store.go` `nameKey`). Frontend duplicate checks should mirror that exactly: trim, then `Set.has(trimmed)` over `rows[].name`. Do not lowercase.
