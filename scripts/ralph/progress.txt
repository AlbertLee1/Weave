## Codebase Patterns
- 每个前端 story 是一个独立纯逻辑模块：`web/src/features/vertex/<feature>/<name>.ts` + `<name>.test.ts`，不依赖 React，让 vitest 在 happy-dom 之外直接驱动。
- 测试命名沿用 BDD：`describe('VTX-### <feature>')` + `it('given_<State>_when_<Action>_then_<Outcome>')`；时间常量用 `new Date(...).getTime()` 写绝对时间戳，可读且稳定。
- compare windows 已在 VTX-079 (`web/src/features/vertex/timeSeries/compareWindows.ts`) 提供，新 story 直接复用，不要重复实现。
- vitest 配置已支持 `vi.useFakeTimers()`，定时器/防抖类 helper 用假时钟测试。
- 项目根目录 `tsconfig` 有 `erasableSyntaxOnly`，预先存在的两处错误 (`sdk/typescript/src/vertex.ts`、`src/vertex/SdkVertexClient.test.ts`) 与本 stream 无关。
- uPlot 类型用 `import type uPlotCtor from 'uplot'`，options 写 `uPlotCtor.Options`（沿用 `MultiSeriesChart` / `TimeSeriesChart` 现有模式）。注意 `select` 配置如果只写 `{ show: false }` 会 TS2739（必须给 left/top/width/height），干脆省略 `select`，默认就是禁用。
- `src/components/__tests__/admin-removed.test.tsx` 是已知 flaky：在完整 vitest 套件里偶尔超时（5s import App.tsx），单独跑稳定通过。本 stream 不要为它修代码。

- **Learnings for future iterations:**
  - BDD spec 给的 URL 路径形式（`/quiver/{objectRid}/{property}`）与现有 React Router 路由（`/quiver/:ontology/:rid`，rid 是 dashboard rid）冲突，不能直译。采用 query param 形式 `/quiver/{ontology}?objectRid=...&property=...&objectType=...&primaryKey=...`，让 QuiverPage 接 `useSearchParams` 在 mount 时 prefill 一个 SeriesSpec，等价语义但保留现有路由不变。这种 spec-vs-codebase 冲突优先选 query param 而不是加新路由 — 改 routing 是更大 blast radius，应由专门 routing story 决定。
  - encodeURIComponent 对路径段、URLSearchParams 对 query：两者编码规则不同（` ` 在路径里编 `%20`、在 query 里编 `+`）。测试断言时如果跨路径/query 比较，分别用对应 API 解码，不要直接字符串比较。

- **Learnings for future iterations:**
  - cell key 用 *三段* `${scenarioRid}::${rowRid}::${paramName}` 而非 VTX-039 的两段（`${rowRid}::${paramName}`）—— Pane 同时显示多个 Scenario 列，每列的同一 (row, param) cell 是独立 override 槽位；如果省略 scenarioRid，跨列的 setOverride 会互相覆盖。React 接线层在渲染表格时按 (scenario.rid, row.rid, param.name) 三元组组 key 反查。
  - update vs create 都走 POST 而不是 PUT —— 后端 endpoint 是 `POST /scenarios/{rid}/overrides` 单一写入路径，服务端按 (scenarioRid, rowRid, paramName) 复合唯一约束做 upsert，前端用同一个 buildCreateOverrideRequest 即可。本模块的 `CellEditDecision` 仍然区分 create / update kind —— 信息保留给上层（UX toast 文案 "Override added" vs "Override updated" + 分析埋点 "scenario.override.created" vs "scenario.override.updated"），代价只是一个 discriminant 字段。如果未来后端拆 PUT，改 buildUpdateOverrideRequest 即可，外部 API 不破。
  - invalid 输入"不静默丢 existing" 是重要不变式：用户在已有 override 的 cell 里手滑输入 "abc"（valueType=number），blur 时模块返回 `{kind:'invalid', reason:'not_a_number'}`，*不* 返回 delete。React 接线层 toast 提示 + 把 cell 值回滚到 existing.value 而不是显示空。如果模块把 invalid 当 empty 处理→静默 delete，用户会丢数据。测试 `given_invalid_input_with_existing_when_resolve_then_invalid_does_not_emit_delete` 显式锁死。
  - parseScalarInput 拒 '1'/'0' 当 boolean 是刻意选择：数据库 / OMS 端常见把 boolean 序列化成 0/1，但用户视角的 UI 输入里 '0' 应该作为 "number 0" 而非 "false"。让 valueType=boolean 时仅接受字面值 'true'/'false'（大小写不敏感），歧义留给上层 React 用 checkbox / Radix Switch 组件天然规避输入字符串。
  - parseScalarInput 拒 Infinity / NaN 文字（"Infinity" / "NaN"）走 Number.isFinite 路径：Number("Infinity") = Infinity，会通过 Number.isNaN 但不会通过 Number.isFinite。Number.isFinite 是正确的过滤器；vitest 测试两个都验证一遍防止有人误改成 Number.isNaN（看似等价实际放过 ±Infinity）。
  - FROZEN_SCENARIO_TOOLTIP="Scenario is frozen." 与 createDialogs.IMMUTABLE_SCENARIO_MESSAGE="Scenario is immutable. Duplicate to modify." 是两条不同 UX 路径：tooltip 出现在 disabled cell hover 上（被动信息），immutable message 出现在用户主动绕过 guard 时的 toast / Modal（主动提示 + 行动指引）。语义不同，文案分开。测试用 `toLowerCase().toContain('scenario is frozen')` 防大小写漂移又不锁死标点。
  - ScenarioFrozenError 与 ScenarioImmutableError 是两个独立 Error 子类。它们 message 不同（FROZEN_SCENARIO_TOOLTIP vs IMMUTABLE_SCENARIO_MESSAGE），name 不同，承担的语义角色也不同（cell 级 vs scenario 级）。共享 `ScenarioLike` interface 但不共享 Error class —— React 错误边界可以按 `error.name` 路由到不同 UI 反应（cell tooltip 不需要弹 Modal）。
  - immutable update（`setOverride` 不 mutate 原 map）与 VTX-036 reducer 风格保持一致：测试 `given_setOverride_when_called_then_does_not_mutate_original_map` 显式断言 —— Zustand store 用 immer middleware 时不破免疫，但本模块同时支持纯对象 store（不用 immer），不 mutate 让两种用法都安全。removeOverride 同理：用 spread + delete 而不是 in-place delete。
  - resolveCellEdit 的"value 未变 → noop"判断用 `===` 严格相等。number/string/boolean 三类 scalar 都安全（不会有 NaN 自比假），与 React props 浅比较哲学一致。如果未来 ScalarOverrideValue 扩展到 Date / 数组，需要在 noop 判断改为深比较 helper，否则会产生冗余 POST。
  - dev-browser skill 不可用 — 黄色边框样式、disabled cell hover tooltip、DELETE 后高亮消失的浏览器验证留到 React 接线 story。本 story 仅交付纯逻辑 + 副作用工厂（请求构造器），React 层 fetch wrapper 直接消费 OverrideApiRequest。
