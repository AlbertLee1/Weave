## Codebase Patterns
- Scheduler loops expose Start/Stop lifecycle methods and run an immediate first cycle before ticking on an interval.
- Scheduler goroutines should capture lifecycle channels into locals before entering the select loop; Stop may mutate struct fields under lock while the goroutine is still running.
- Race-enabled tests that observe goroutine-updated fixture state should use atomic or mutex-protected counters.
- Tests asserting context cancellation should leave only the cancellation path ready after cancel; unblocking a success path in the same window makes select-based computes nondeterministic.
- Sidebar tests that assert auth-gated admin links must wait for auth-gated UI state; ontology route links can render before `/api/v2/me` resolves and are not proof that admin identity has loaded.
- Wall-clock performance tests should detect Go race/coverage instrumentation and either relax budgets or reduce workload while leaving strict budgets in standard runs and benchmarks.
- Performance-profile contract tests are useful for CI-host timing repairs because they verify the intended profile selection deterministically instead of depending on local wall-clock slowness.
- Large streaming export tests should use CI-safe row counts that still exercise rollover, disk size growth, and heap ceilings; full-envelope throughput belongs in benchmarks or dedicated performance jobs.
- Seeded random operators must canonicalize unordered candidate universes before applying PRNG selection; seeding only the PRNG is insufficient.
- For performance CI repairs that cannot be reproduced locally, add deterministic profile-contract tests for the budget/workload selection and keep wall-clock tests as separate gates.
- Coverage floor gates should be calibrated against current CI-backed package measurements; aspirational floors belong in a separate coverage-improvement story so PR CI remains actionable.
