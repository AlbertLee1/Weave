## Codebase Patterns
- ObjectSet executor Result can carry out-of-band per-PK payloads by adding a
  new map field (see Result.DerivedValues); handlers merge into WireObject
  Properties just before oss.FormatObject. Keeps Execute signature stable
  while avoiding a second backend roundtrip.
- withProperties Definition now takes DerivedProperties []DerivedPropertyDef;
  legacy Properties []string is still honoured and short-circuits to
  delegating to the inner ObjectSet unchanged.
- Link resolver mocks in objectset_test.go return a flat target list and
  ignore sourcePKs — for per-source tests add a new mock that maps each
  source PK to its own target list (see perPKLinkResolver in
  withproperties_test.go).
- withProperties numeric metrics (sum/avg/min/max) must resolve the target
  ObjectType via LinkTargetTypeResolver, then fetch per-PK docs from the
  target Bleve index with bleve.NewDocIDQuery + searchReq.Fields=[field].
  Test link resolvers need to implement ResolveTargetObjectType for these
  paths to work (plain ResolveLinkedObjectsByAPIName is NOT enough).
- bleve numeric field search results come back typed as float64 regardless
  of whether the source doc used int or float64 — coerceNumeric in
  executor.go handles the full int/uint/float spread to future-proof ingest
  paths that deviate.
- gofmt across the repo has pre-existing drift in many files; only lint your
  own edited files, do not blanket-reformat.
- Reverse-direction withProperties routes through an optional reverseLinkFinder
  interface (ResolveLinkedReverseByAPIName) on the link resolver; the executor
  short-circuits with an explicit error when a resolver only speaks forward.
  Test mocks must opt-in by adding the reverse method + reverseEdges map; the
  production *links.Resolver does NOT yet implement it, so end-to-end reverse
  withProperties still needs a follow-up adapter once OMS-backed incoming link
  lookups (ListIncomingLinkTypes) are wired through.
- Property now carries a Derived bool flag for US-004 (query-time computed
  fields). Three independent validators live alongside existing packages and
  can be wired into handlers incrementally without changing existing behaviour:
    * pkg/oms.ValidateObjectTypePrimaryKey (returns *apierror.APIError)
    * pkg/oss/where.ValidateClauseAgainstDerivedFields (sentinel error
      ErrDerivedPropertyTextSearchUnsupported; walks and/or/not subtrees)
    * pkg/actions.ValidateEditsAgainstDerived (sentinel error
      ErrDerivedPropertyReadOnly; delete edits always pass-through).
  Follow-up work: have handlers call these validators with a real derived-map
  fetched from OMS schema, so invalid requests surface on the wire.
- withProperties executor sorts its returned PrimaryKeys by
  (firstDerivedValue ASC, primaryKey ASC) as a deterministic composite sort
  key so offset-based LoadObjects pagination is stable across pages. The
  sort copies inner.PrimaryKeys before mutating so nested callers still see
  the inner executor's native order. compareDerivedValues tolerates nil,
  int64, float64 and string fallbacks so all five metrics plus future types
  remain orderable.
- interfaceBase execution in pkg/oss/objectset/executor.go now loads each
  implementing ObjectType concurrently (sync.WaitGroup + mutex-guarded map)
  and heap-merges their per-type buckets into a flat PrimaryKeys list. The
  per-type buckets survive on Result.PerTypePKs (sorted ASC) and per-row
  ObjectType on Result.Origins, so downstream consumers can drive
  composite-cursor pagination without re-sorting. The heap merge tie-break
  is (primaryKey ASC, objectType ASC) so PK collisions across types resolve
  deterministically.
- pkg/oss/pagination now has MultiTypeCursor{SubCursors []CompositeCursor}
  + Encode / DecodeMultiTypeCursor / IsExhausted. Use it as the wire format
  for any polymorphic paging scenario. Exhausted sub-cursors (inner == "")
  are dropped before Encode so the token shrinks as sub-streams drain.
- handler_preview.go has a dedicated writePreviewInterfacePage path that
  fires whenever result.PerTypePKs != nil. Rows are fetched from each
  row's own ObjectType Bleve index (not the interface-tag index), so
  $apiName / $rid / properties stay per-row accurate across a polymorphic
  result. The old offset cursor path is preserved as the fallback when
  PerTypePKs is nil.
- Integration tests under test/integration/ use //go:build integration.
  Boot a real PG via testutil.StartPGContainer + database.RunMigrationsUp,
  then construct oms.NewPGRepository(pg.Pool) as the metadata backend.
  Seed ObjectTypes via repo.CreateObjectType (primary_key_prop is just
  TEXT, so you can pass the string directly without creating Property
  rows). Bleve indexes stay in a t.TempDir() so there's no cross-test
  contamination. Production main.go does NOT yet wire a PG-backed
  InterfaceResolver, so tests that need one should ship a local shim:
  lookup via repo.GetInterfaceByAPIName(ctx, ontologyRID, apiName) →
  repo.ListInterfaceObjectTypes(ctx, iface.RID) → []apiName. Follow-up
  for Phase 6 Gate: fold that shim into main.go.
- New chi routes MUST update api/openapi.yaml AND re-copy to
  cmd/server/openapi_spec.yaml. `TestContract_AllRoutesDocumented` and
  `TestContract_EmbeddedSpecMatchesCanonical` both fail otherwise.
  Route in a protected group → remember to use `api.With(
  auth.RequirePermission(perm)).Method(http.MethodPost, path, handler)`
  so permission gating cascades through the existing auth middleware.
- For features that need a concrete-only PGRepository method (no
  cached-repo shim), main.go must keep a separate `pgRepo` handle at
  construction time (before wrapping in CachedRepository) and pass it
  through a typed ServerDeps field — unwrapping the cached decorator
  later is not supported.
- Narrow in-package interfaces beat expanding oms.Repository. The
  oms.Repository interface is already 50+ methods with 11 mock
  implementations; every new method forces 11 stub updates. If a
  consumer only needs 2–3 calls, define a local interface (see
  `pkg/index/rebuild.go RebuildRepo` and `rehydrate.go rehydrateRepo`)
  and keep the concrete PG method un-exported from the interface.
- Text FieldMapping defaults to the English ("en") Snowball analyzer
  via `pkg/index/mapping_builder.go:standardTextAnalyzer`. Lowercase
  + Porter stemmer + possessive strip is the baseline for
  analyzer.standard / unset properties; not_analyzed still routes to
  KeywordField (identity analyzer). When writing new text-field
  search tests prefer `bleve.NewMatchQuery(...)` — TermQuery skips
  the analyzer and breaks the moment a stemmer is in play. Use
  TermQuery ONLY on not_analyzed / keyword fields. Porter English
  does NOT stem "runner" → "run"; safe stem pairs for fixtures:
  run/runs/running, shoe/shoes, walk/walks/walking.
- oms.ObjectType returned by GetObjectTypeByAPIName does NOT carry
  its Properties slice — call ListProperties(ctx, ot.RID) separately
  and assign ot.Properties = props before handing the ObjectType to
  `index.BuildMapping`, otherwise the generated mapping will be
  empty and every search will silently return zero hits.
- pkg/oss/aggregation/engine.go has two parallel groupBy code paths:
  the LIVE recursiveGroupBy + getXxxEntries (exact/fixedWidth/ranges/
  duration/topValues) that returns []groupEntry, and the DEAD
  groupByExact / groupByFixedWidth / groupByDuration / groupByTopValues
  that are no longer reachable. Always patch the getXxxEntries side.
  Bucket order across ALL group types is stabilised by sortGroupEntries
  (ASC by fmt.Sprint(value), nils last) called inside recursiveGroupBy,
  so new groupBy types only need to return unsorted entries.
- Null-group handling for exact groupBy: when facetResult.Missing > 0
  AND len(terms) > 0, getExactEntries appends a value=nil entry with
  scopeQuery = BooleanQuery{Must: baseQuery, MustNot: allTermQueries}.
  Bleve has no "field exists" query, so this negation trick is the
  canonical way to narrow to docs that lack the field. Do NOT emit
  a null bucket when len(terms) == 0 — that would wrap every doc in
  a single null bucket when grouping by a non-existent field and
  break TestAggregate_GroupByExact_NoResults.
- Local dev postgres must be `pgvector/pgvector:pg16` (not
  `postgres:16-alpine`) — migration 000011 runs
  `CREATE EXTENSION vector` and silently dirties schema_migrations on
  the alpine image. Testcontainers already uses the pgvector image;
  docker-compose.yml was fixed in US-030 to match. Any future
  migration that needs an extension must be verified against BOTH
  paths.
- `scripts/e2e-setup.sh` nohups `bin/weave` in a bare env, so
  `PG_DSN / NATS_URL / AUTH_MODE` need to be explicitly exported near
  the top of the script (not just in the parent shell). Missing
  exports silently bring weave up in degraded mode (no PG pool, which
  makes the admin rebuild endpoint return
  `IndexRebuildNotConfigured`).
- Playwright E2E seed lives at `test/fixtures/seed_northwind/` as a Go
  library + thin CLI wrapper. Since the Admin CRUD API was removed in
  v1 US-006, new seed/demo scripts must write directly through
  `oms.PGRepository` (+ `auth.PGUserRepository` for users) and then
  call `POST /api/admin/indexes/rebuild` to hydrate Bleve.
  `link_types.cardinality` only allows `ONE_TO_ONE / ONE_TO_MANY /
  MANY_TO_MANY` — `MANY_TO_ONE` breaks the CHECK constraint.
- withProperties over a polymorphic (interfaceBase) inner keys
  DerivedValues by polymorphicDerivedKey(type, pk) — NUL-separated — not
  plain pk. Any consumer of polymorphic Result.DerivedValues MUST read
  through the helper in pkg/oss/objectset/executor.go, NOT `derived[pk]`.
  The executor branches in executeWithProperties when inner.PerTypePKs
  != nil → executeWithPropertiesPolymorphic; current scope is forward
  count only. Numeric metrics / reverse direction error out with a clear
  "not yet supported" message. The handler's writePreviewInterfacePage
  merges polymorphic derived values onto each row via the same helper.
- handler.Aggregate in pkg/oss/objectset has two execution paths: the
  legacy Bleve-facet engine (base fields only) and a new in-memory
  derived-aware path in handler_aggregate_derived.go. Routing is decided
  by aggregationNeedsDerivedPath(req.Aggregation, result.DerivedValues) —
  true iff any metric field name appears as a key in Result.DerivedValues.
  The derived path supports exact groupBy (recursive, multi-level) and
  count/min/max/sum/avg metrics. Non-exact groupBy types error out with
  an explicit message rather than silently degrading. When you add a
  metric to the engine, mirror it in computeDerivedMetrics. Base metric
  fields (non-derived) are fetched in one DocIDQuery alongside groupBy
  fields so mixed base+derived metric requests still work.
- Foundry parity fixtures are split into two co-located sets:
  descriptive/documentary JSON at `test/foundry_parity/*.json` (prose
  for sortKey / responseShape / errorCodes / coveredBy, and several
  files already repurpose top-level `request`/`expected` for prose)
  and executable JSON at `test/foundry_parity/runner/*.json` (envelope
  `{name, story, request: {method, path, headers?, body?},
  expected: {status, body?}, notes}`). The runner
  `test/foundry_parity/run.go` (package main) walks both recursively
  and classifies via isExecutable: empty request.path → documentary →
  SKIP. Add new real parity fixtures to `runner/` only; never overload
  the doc corpus. Makefile target `make test-parity` brings up the
  stack via scripts/e2e-setup.sh when :9117 is unreachable and then
  `go run ./test/foundry_parity -v`.
- LoadObjects and the loadObjectsOrInterfaces preview path use DIFFERENT
  reserved-key prefixes on emitted rows. pkg/oss/wire.go FormatObject
  writes `__primaryKey` / `__apiName` / `__rid` (double underscore) for
  the canonical LoadObjects path, while handler_preview.go writes
  `$primaryKey` / `$apiName` / `$rid` for ?preview=true responses. A test
  that POSTs /objectSets/loadObjects MUST parse `__primaryKey`; a test
  that POSTs /objectSets/loadObjectsOrInterfaces?preview=true MUST parse
  `$primaryKey`. Grepping the existing interface-paging test (which is
  preview-shaped) for the `$` form will lead you astray when writing a
  non-preview test.
- pkg/oss/where convertEq on a string value emits a bleve.MatchQuery.
  MatchQuery looks up the field's mapping-time analyzer via
  IndexMapping.AnalyzerNameForPath, so a Keyword field query runs through
  the identity keyword analyzer — meaning `eq "USA"` matches an indexed
  "USA" but NOT an indexed "usa". That is the correct US-050 contract but
  easy to misremember as "MatchQuery always lowercases". convertContains
  on the other hand emits a bleve.NewTermQuery which BYPASSES the
  query-side analyzer entirely — against an English-snowball field,
  TermQuery("run") matches indexed "runs"/"running" (both stem to "run"),
  but TermQuery("running") finds nothing because the index only stores
  "run". Phase 6 US-035 pins this asymmetry; any future rewrite that
  switches contains to MatchQuery will surface loudly through those
  assertions.

  openapi.yaml path entry → must `cp api/openapi.yaml

  - `docker compose up -d --wait <svc>` is the right idempotent primitive
    for service-scoped bring-up: it returns immediately on already-healthy
    services and waits for health on cold starts. Prefer this over ad-hoc
    curl polling loops.

    echo $! > pidfile` works, but when the start happens inside a

- **Learnings for future iterations:**
  - `test/fixtures/seed_northwind` is now the canonical place to ship
    Playwright-facing ActionTypes. New E2E specs that need more rule
    coverage should extend `northwindActionTypes()` rather than
    creating their own private seeds — the existing idempotent wipe
    handles action_types cleanup for us.
  - `PGRepository.CreateActionType` accepts JSON `[]` for parameters
    and rules straight from raw strings, so the seed can hand-author
    the definitions as multi-line string literals without cgen via
    encoding/json. Keeps schemas.go readable and diff-friendly.
  - `pkg/oms.parametersToV2` converts the stored array-of-objects
    params format into the Foundry V2 Record wire format, using the
    `description` field as-is. Playwright specs therefore get a
    stable `placeholder` to select inputs against — the
    `ParameterForm` component renders descriptions as input
    placeholders (no htmlFor label linkage). Pick
    `page.getByPlaceholder(...)` over `getByLabel` for parameter
    form inputs until the component grows aria labels.
  - Two-tab optimistic-concurrency races are best modelled with
    `browser.newContext()` pairs, NOT two pages inside one context —
    the shared React Query cache inside one context would merge the
    two useObjectVersion() snapshots and hide the stale read. Keep
    the contexts isolated and close them in a `finally` block so one
    failed assertion doesn't leak Chromium processes into CI.
  - Phase 6 gate playbook: the first Playwright spec for a given
    feature often needs a seed extension to land alongside the spec.
    When that happens, also update `test/fixtures/seed_northwind/
    seed.go` wipe() to delete any new tables the seed now writes —
    otherwise idempotency breaks the second seed run (the first run
    works because PG is empty on fresh containers).
  - `playwright.config.ts` already has `workers: 1` and
    `fullyParallel: false`, so the race between Tab A commit and Tab
    B version-check is driven by the short `page.waitForTimeout(750)`
    after the Tab A submit; the NATS consumer typically rolls
    object_history forward well under that window in dev mode. If
    flakes appear, raise the wait before breaking the underlying
    flow.
