## Codebase Patterns
- Browser dogfood is mandatory for Vertex/Sigma runtime changes: Vitest/jsdom and `make web-test` can pass while the real Vite dev server throws React/Sigma runtime errors.
- For this story, do not mark complete based only on unit tests; preserve enough evidence for Hermes to re-check `/vertex/new` in a fresh browser context and inspect console errors.
- Heavy ESM-prebundled libs that import `react` (e.g. `@react-sigma/core`) MUST live in `vite.config.ts` `optimizeDeps.include` when they sit behind a `React.lazy` boundary. Vite would otherwise discover them on first navigation, kick off a mid-flight re-optimize, and serve a fresh chunk whose `react` reference differs from the one already mounted — producing `Invalid hook call` / `useRef returning null` on first load while a refresh works fine.
- Pair `optimizeDeps.include` with `resolve.dedupe: ['react', 'react-dom']` so the dev server can never resolve two React instances across nested `node_modules` layouts.
- Vitest tests that need to validate `vite.config.ts` content can use Vite's `?raw` query (`import src from '../../vite.config.ts?raw'`) — avoids `node:fs` imports that aren't typed in `tsconfig.app.json`.

## 2026-05-16 00:16 - VTX-126 — Fix Vertex /vertex/new real-browser React/Sigma runtime crash
- **Diagnosis (matches the "refresh fixes it" symptom):**
  - `web/src/App.tsx:66-68` lazy-loads `VertexWorkspacePage`, so the bundler chunks `@react-sigma/core` + `sigma` + `graphology` behind the route.
  - `web/vite.config.ts` had no `optimizeDeps.include` and no `resolve.dedupe`. On first navigation to `/vertex/new`, Vite discovered the Sigma/graphology deps on the fly, triggered a dependency re-optimization, and served a freshly bundled chunk whose `react` module instance was different from the one already mounted in the app shell. `@react-sigma/core`'s `useRef`/`useContext` calls then hit a null dispatcher → `TypeError: Cannot read properties of null (reading 'useRef')`. After the optimize completes and the page reloads, both halves of the app share the same prebundled React, so a manual refresh worked.
- **Fix:** added explicit prebundling + React dedupe to `web/vite.config.ts`:
  - `resolve.dedupe: ['react', 'react-dom']` — guarantees a single React instance regardless of nested `node_modules` layouts.
  - `optimizeDeps.include: ['@react-sigma/core', 'sigma', 'graphology']` — Vite prebundles these at dev-server boot, so the first `/vertex/new` visit never trips a mid-flight re-optimize.
- **Regression guard:** `web/src/__tests__/viteConfig.vertex.test.ts` — two Vitest cases that import `vite.config.ts` with the `?raw` suffix and assert the `optimizeDeps.include` entries + the `resolve.dedupe` list are present. Would have failed on the previous config; passes now.
