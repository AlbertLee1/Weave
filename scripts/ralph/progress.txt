## Codebase Patterns
- 后端 dependency boot 顺序在 cmd/server/main.go 的 deps struct：Config → PG → IndexManager → LinkResolver → OSSService → ObjectSetStore → NATS Consumer → ActionExecutor → router。新加跨包依赖往里挂时，遵循"select backend by `PGPool != nil`"模式（参考 GeotemporalStore / TimeSeries / Marking 选型）。
- `internal/cliclient` 是 weave-cli 公用 HTTP 入口；新增子命令复用它的 base URL / auth token 解析，不要重新发明轮子。
- httptest.Server 模式：CLI / bridge 测试一律用 httptest 而非启 cmd/server，能避免 PG/NATS 依赖。OSV2-303 的 cmd/weave-mcp/main_test.go 是参考实现。
- MCP 改动同步三处：`pkg/mcp/server.go`（dispatch）+ `pkg/mcp/<feature>.go`（handler）+ `pkg/mcp/doc.go`（客户端发现说明）。漏改 doc.go 是常见漂移源。
- `pkg/tracing` 已经装了 W3C TraceContext + Baggage 复合 propagator；跨进程 / 跨 transport 传 trace 直接 `otel.GetTextMapPropagator()` Inject/Extract，不要再造一个 propagator。
- 真正的 OSv2 自评分见 docs/PRD-Weave-OSv2-深度复刻-V2.md §2.1 矩阵；本轮路线图见 tasks/prd-osv2-iteration-roadmap.md。
- 测试范式：TDD（Red → Green → Refactor）。每 story 先写命名 TestX_Given_State_When_Action_Then_Outcome 的失败测试（go test 表驱动 / Vitest），跑一次确认 fail；再写最小实现转绿；再视情重构。
- 算法/性能 story 在 `bench/` 下加 benchmark；安全 story 必有负向测试；前端 story 必走 dev-browser skill 验证。
- `pkg/funnel.Broadcast` 既是 SSE fan-out hub 也是 replay 缓冲：`SubscribeWithReplayWindow(buffer, fromSeq)` 返回 `(id, ch, outOfWindow)`，时间窗 + ring 容量双重剪裁；SSE handler 把 outOfWindow → 410 Gone（在写 text/event-stream header 之前）。修 SSE 行为时优先改 broadcast 而不是各处自建 ring。

- Files changed:
  - pkg/funnel/broadcast.go — 加 window + nowFn + pruneByTimeLocked + cursorOutOfWindowLocked + SubscribeWithReplayWindow + NewBroadcastWithWindow（旧 SubscribeWithReplay 现在是 Window 版的 thin wrapper，向后兼容）。
  - pkg/funnel/broadcast_window_test.go — 4 个新测试覆盖剪裁、越界、追平、零 cursor。
  - pkg/oss/subscribe_sse.go — handler 在写 SSE header 之前先调用 SubscribeWithReplayWindow，outOfWindow=true 时写 410 Gone（`apierror.NewGone("SSEReplayWindowExceeded", ...)`）；payload 现在包含 seq/type/rid/properties + 遗留 eventType/object。
  - pkg/oss/subscribe_sse_us459_test.go — 4 个 PRD-spec 测试（since 别名、410、并发 ack、payload 形状）。
- **Learnings for future iterations:**
  - SSE handler 必须先做"会拒绝整个请求"的检查（429 限流、410 cursor 越界）再写 `text/event-stream` header，因为一旦 WriteHeader(200) + Flush 之后状态码就锁死了，错误只能塞 data 帧——SDK 没法区分"流自然结束"和"业务拒绝"。
  - 双写新旧 payload 是无痛上线 PRD 新约定的常用招：legacy keys 留给现有 web/SDK 消费者，canonical keys 给新 SDK；React hook (`web/src/hooks/useObjectSetSubscription.ts`) 这次完全不用动。
  - cursor 越界判定需要区分三种情形：fromSeq==0（新客户端）、fromSeq>lastSeq（客户端跑前面去了，回放 0 条但不 410）、fromSeq<ring 头部 seq-1（真丢事件，410）。中间分支极易写漏，broadcast_window_test 的 4 个正反例就是为了把它们都钉住。
  - `pkg/apierror.NewGone(name, params)` 自带 NOT_FOUND-shaped 410；不要自己 `w.WriteHeader(410)` 写 ad-hoc body。
