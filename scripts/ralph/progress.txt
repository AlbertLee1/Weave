## Codebase Patterns
- Migrations 序号已用到 000106；新增使用 000107+。一对 `*.up.sql` / `*.down.sql`，up 必须用 `IF NOT EXISTS` / `DO $$ ... IF NOT EXISTS ... END$$` 保证幂等，down 必须按 FK 依赖反向 DROP。
- 集成测试用 `//go:build integration` + `testutil.StartPGContainer(t)`（pgvector/pgvector:pg16，每 case 独立容器，~1.2s 启动）。运行：`go test -tags integration ./... -run TestX -v`。需要 Docker。
- TimescaleDB 专用集成测试用 `testutil.StartTimescaleDBContainer(t)`（timescale/timescaledb:latest-pg16，自带 timescaledb 扩展）。仅在确实需要 hypertable / continuous aggregate 时用，启动 ~1s；其余 PG 集成测试继续用 pgvector 镜像以避免额外 1.4GB 镜像下载。
- 涉及 TimescaleDB 扩展的迁移用 `IF EXISTS (SELECT 1 FROM pg_available_extensions WHERE name = 'timescaledb')` DO-block 包裹 `create_hypertable` / 连续聚合，保证在 pgvector 镜像上也能跑通（普通表仍创建，hypertable / cagg 缺席而已）。
- 测试命名遵循 PRD tddConvention：`Test{Feature}_Given_{State}_When_{Action}_Then_{Outcome}`。
- 校验 column / index 存在：`information_schema.columns` / `pg_indexes`（`indexdef ILIKE '%(col_a, col_b)%'`）。
- Module path: `github.com/liyang/weave`，迁移文件路径由 `testutil.MigrationsDir()` 自动向上搜索 8 层定位 `migrations/`。
- Vertex 命名前缀：RID 形如 `ri.vertex.{realm}.{resourceType}.{uuid}`；与现有 `ri.ontology.*` 区分但共用 PG schema。
- Repo 风格遵循 pkg/oms.Repository：小接口、ctx-first、sentinel error（`ErrXxxNotFound` / `ErrXxxImmutable`）让调用方可 `errors.Is`。PG 实现写 `var _ Repo = (*PGRepo)(nil)` 编译期断言接口满足。
- 应用层并发写 + 状态翻转：`SELECT ... FOR UPDATE` + tx 阻塞并行 AppendEdit / Freeze，避免 immutable 翻转后还能追加 edit。pgx.BeginTx + defer Rollback 是标准模式。
- pgx 的 JSONB 写法：`json.RawMessage` 或 `[]byte` 直传，pgx 会自动处理 jsonb 类型；空切片传 nil interface 防止某些版本 panic。`NULLIF($n, '')` 把空字符串映射为 NULL，匹配 schema 的 nullable text 列。
- 纯函数（无 DB / 无 IO）测试：放同包 `*_test.go`（外部包名 `scenarios_test`），不需要 `//go:build integration`，`make test` 默认就跑；Benchmark 用 `go test -bench BenchmarkX -run='^$' -benchmem ./pkg/...`，跳过普通测试只跑 bench。

- **Learnings for future iterations:**
  - VTX-028 hypertable 上做 `time_bucket(INTERVAL, ts)` 直接走 raw chunks — 不需要走 cagg_5min。cagg 是 VTX-030 REST handler / VTX-060 frontend extended label 上的优化路径（当 bucket=5m 时可以直查 `cagg_5min`，更省 CPU）。
  - SQL 里 INTERVAL 不能直接 `$1` bind 一个 Go time.Duration——pgx 会拒。用 `'%d microseconds'` 字符串 + `$1::INTERVAL` 显式 cast。
  - `pgx.ErrNoRows` 不会从 `MAX(ts)` 出来（聚合永远返回一行）；空表场景 `last` 会被 scan 成 `time.Time{}` (zero)，靠 `last.IsZero()` 跳过 warning 计算。如果以后 schema 改成 ts NOT NULL DEFAULT NOW()，要重新评估这点。
  - `ScenarioOverlayReader` 接口只暴露 `GetWindowedScalarOverride`，故意不引用 `pkg/scenarios` — 让 VertexService 测试可以纯用 stub overlay 跑，PG container 里不必塞 scenario 数据。VTX-030 REST handler 那层再做 `*scenarios.PGRepo` → `ScenarioOverlayReader` 的 adapter。
  - 测试断言 `len(res.Points)==N` 时记得 `From`/`To` 是半开区间 `[From, To)`：30min 区间 + 5min bucket = 6 桶 (00-05, 05-10, ..., 25-30) 而不是 7。
