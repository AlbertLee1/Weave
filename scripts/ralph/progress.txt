- i18n bootstrap: prod entry `main.tsx` does `import './i18n'` for the side-effect init; vitest `src/test/setup.ts` does NOT. Any component that calls `useTranslation()` must side-effect-import `'../i18n'` itself, otherwise `t(key)` returns the raw key in component tests that don't transitively reach the i18n module. Pattern: `import { useTranslation } from 'react-i18next'; import '../i18n';`.
- i18next plural collision: passing `{ count: N }` to `t()` makes i18next route to `_one`/`_other` plural variants; if you only define a single non-suffixed key, lookup fails and the raw key leaks into the UI. Use a different variable name (e.g. `{ num }`) for non-plural counters.

- Coverage gates: backend uses `cmd/covercheck` (US-056 / PC-C13) reading `coverage/thresholds.json`. Floor entries are full Go import paths; the new `excludeFiles` array (VTX-122) filters cover-profile lines by *path suffix* before aggregating, so PG-bound files (`pg_repo.go`, `pg_store.go`, `archive_db.go`, `vertex_service_pg.go`, `pg_templates.go`) — exercised only under `//go:build integration` — don't drag the unit-test floor. When adding a PG implementation to a covered package, split it into its own file and add the suffix to `excludeFiles`. Frontend uses Vitest `coverage.thresholds` per-glob: `'src/vertex/**/*.{ts,tsx}': { lines: 75, ... }` keeps the floor scoped to Vertex without forcing legacy Workshop/Explorer up.
- Backend split pattern: keep pure (compress / option setters / SQL string builders) functions in the main file, move DB-bound entrypoints (`db *sql.DB` or `*pgxpool.Pool` parameters) to a sibling `*_db.go` / `*_pg.go` file that's added to `coverage/thresholds.json` excludeFiles. Both files share the same package; the integration test file (`//go:build integration`) keeps targeting the package as a whole.
- Vitest coverage tip: tests that inject stubs (`loader={async () => ...}`) bypass the `defaultLoader` fetch code in the component, leaving it uncovered. Add a sibling `*.defaults.test.tsx` file that overrides `globalThis.fetch` via `vi.fn` to exercise the production fetch wrappers — restore the original in `afterEach`.
- Vitest under `--coverage` runs the v8 instrumentation transform which roughly doubles transform time; default `testTimeout: 5000` is fragile for import-heavy tests (`Accessibility.test.tsx`, `admin-removed.test.tsx`). The global `testTimeout: 30000` in `web/vite.config.ts` covers it.
