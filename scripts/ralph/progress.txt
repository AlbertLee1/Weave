## Codebase Patterns
- Global r.Use() chi middleware runs BEFORE route resolution, so
  chi.URLParam returns "". For URL-param-dependent middleware
  (e.g. rate limiting keyed by ontology), use pattern-based segment
  extraction (compiledRule.extractParam) instead of chi.URLParam.
- pkg/security hosts the row-level policy engine. Extend `Engine.compileRule`
  in place for new rule types (`in`, `markingSubset`, ...); do NOT branch
  callers on policy type. Un-policied ObjectTypes return `MatchAllQuery` so
  callers unconditionally AND-combine Evaluate into OSS Load/Search/Aggregate
  pipelines. Fail-closed when a referenced user attribute is missing
  (`MatchNoneQuery`, not `MatchAllQuery`). Rule JSON tags must match the
  `security_policies.rules` JSONB shape (`type`/`userAttr`/`objectProperty`).
  Policies are keyed by ObjectType RID, not APIName. List-valued rule types
  (`in`, `markingSubset`) share the `buildShouldTermsQuery` helper in
  policy_engine.go — any future Should/MinShould tweak lands in that one
  place so eq/in/markingSubset stay shape-consistent. User markings for
  RuleTypeMarkingSubset live under the fixed key
  `security.userMarkingsKey = "markings"` in `auth.User.Attributes`; US-058
  marking evaluator and US-059 JWT injection MUST use this same key.
- `auth.User.Attributes map[string]any` is the designated surface for policy
  evaluation inputs (dept, region, clearance, ...). US-059 JWT marking
  injection should populate this map, not `Roles`.
- Row-level policy enforcement has TWO hook points. ServiceImpl owns
  `SetPolicyEngine(*security.Engine)` + `compilePolicyQuery` +
  `mergePolicyQuery` for Load/Search/GetObject paths. The ObjectSet executor
  (`pkg/oss/objectset/executor.go`) owns `SetPolicyProvider` against a narrow
  `PolicyQueryProvider` interface — the concrete adapter lives at
  `cmd/server/policy_provider.go` and translates apiName → RID via the
  ontology scope on context, keeping `pkg/oss/objectset` free of a direct
  `pkg/security` import. Single hook inside `executeBase` covers union /
  intersect / subtract via recursion; `executeFilter` gets its own explicit
  hook so the docID ∩ where branch stays self-sufficient. `mergePolicyQuery`
  collapses a MatchAllQuery policy clause to nil to avoid degenerate
  1-clause ConjunctionQuery wrappers.
- `oss.Service` is an interface but `*ServiceImpl` owns the ABAC setters —
  wire them in main.go via `deps.OssSvc.(*oss.ServiceImpl)` rather than
  widening the public interface. Same pattern applies to any future method
  that only the concrete implementation ships.
- ObjectSet executor Result can carry out-of-band per-PK payloads by adding a
  new map field (see Result.DerivedValues); handlers merge into WireObject
  Properties just before oss.FormatObject. Keeps Execute signature stable
  while avoiding a second backend roundtrip.

- pkg/oss/where convertEq on a string value emits a bleve.MatchQuery.
  MatchQuery looks up the field's mapping-time analyzer via
  IndexMapping.AnalyzerNameForPath, so a Keyword field query runs through
  the identity keyword analyzer — meaning `eq "USA"` matches an indexed
  "USA" but NOT an indexed "usa". That is the correct US-050 contract but
  easy to misremember as "MatchQuery always lowercases". convertContains
  on the other hand emits a bleve.NewTermQuery which BYPASSES the
  query-side analyzer entirely — against an English-snowball field,
  TermQuery("run") matches indexed "runs"/"running" (both stem to "run"),
  but TermQuery("running") finds nothing because the index only stores
  "run". Phase 6 US-035 pins this asymmetry; any future rewrite that
  switches contains to MatchQuery will surface loudly through those
  assertions.

- `oss.ServiceImpl` read paths funnel every Bleve hit through a fixed

  applyPropertyVisibility`. Policy drops denied rows first (cheapest
  survivor set first), US-052's markings pass enforces `object ⊆ user`
  via auth.EvaluateMarkings (no-op unless `engine.MarkingsEnabled(rid)`),
  and US-048's column masking runs last on survivors only. Call sites
  are GetObject / ListObjects / SearchObjects / ListLinkedObjects —
  keep future per-row enforcement passes in this chain rather than
  inventing a fourth hook. GetObject collapses any "filtered to empty"
  result into oms.ErrNotFound so existence isn't leaked regardless of
  which stage dropped the row. The marking filter pulls user markings
  from `auth.User.Attributes["markings"]` via the local

  string so JWT-injected shapes and test fixtures share one evaluator.
- Marking-aware ObjectTypes opt in to enforcement via
  `security.Engine.SetMarkingsEnabled(rid, true)`. Evaluate reads the
  flag inside the locked section, threads it through
  `compilePolicies(policies, user, markingsOn)`, and synthesises a
  `Rule{Type: RuleTypeMarkingSubset, ObjectProperty: MarkingField}`
  clause AND-combined with any explicit OBJECT-scope rules. Fail-closed
  "user lacks markings" collapses the whole Evaluate result to
  MatchNone (not `Conjunction{..., MatchNone}`), so downstream caller
  ANDs stay shape-stable. Rule of thumb: future policy surfaces that
  need fail-closed semantics should synthesise a Rule and let
  compilePolicies handle it rather than AND-hook a raw query at the
  caller. SetMarkingsEnabled bumps the per-RID version counter AND
  calls cache.InvalidateObjectType so an attached PolicyCache cannot
  serve stale compiled queries after a toggle.

- Northwind e2e seed now creates an ontology-scoped HasOwner
  interface attached to customer + order + product via
  test/fixtures/seed_northwind/schemas.go:northwindInterfaces() and

- `funnel.BroadcastEvent.Sequence` carries the NATS stream sequence
  number and is both the SSE `id:` line value AND the ring-buffer key
  for US-057 Last-Event-ID replay. `funnel.Broadcast` maintains a
  bounded replay ring (`DefaultBroadcastReplayCapacity = 1024`);
  `SubscribeWithReplay(buffer, fromSeq)` atomically snapshots events
  with `Sequence > fromSeq` into the new subscriber's channel and
  registers it live under the same hub lock, so no event slips between
  replay tail and live head. Publish MUST hold the hub mutex across the
  fan-out loop — an earlier draft dropped the lock between snapshot and
  send and crashed the concurrent subscribe/unsubscribe stress test
  with "send on closed channel". Sends remain non-blocking (select +
  default) so slow subscribers still can't stall the publisher.
  In-process callers that publish with Sequence=0 (e.g. legacy tests)
  bypass the ring — only monotonic non-zero sequences are stored.
  `cmd/server/main.go` SetOnChange forwarder is the single point that
  copies `ChangeEvent.Offset → BroadcastEvent.Sequence`; any alternate
  publisher must do the same for replay to work.

- The `TestContract_AllRoutesDocumented` + `TestContract_EmbeddedSpecMatchesCanonical`
  pair is a hard gate on ANY new route: register a chi path → must add an
  openapi.yaml path entry → must `cp api/openapi.yaml

  codebase. For new functionality that only needs a 2–3 method slice

    for service-scoped bring-up: it returns immediately on already-healthy
    services and waits for health on cold starts. Prefer this over ad-hoc
    curl polling loops.

    PID file while tolerating trailing newlines that nohup or editors
    inject. Avoid `$(cat file)` — it does word-splitting but keeps the
    newline on some shells.

    review only on this box (no shellcheck binary). Future CI should

  - `pkg/oss/where` now carries TWO parallel evaluators: ConvertToBleveQuery
    for the canonical Bleve-indexed read path, and MatchClause for any

    evaluators. The Bleve side is a TermQuery against a stemmed text

    replay of the Bleve query plan — clients that need exact Bleve
    semantics must re-query after reconnect anyway.

    do NOT delete it outright, it is still a cleaner symbol for
    callers that only need the type name.
  - combineClauses produces a `where.WhereClause` by re-marshalling
    the collected sub-clauses into the synthetic "and" envelope's
    Value. An earlier draft tried to build the envelope by string
    concatenation — that works but bypasses the type system. Prefer
    json.Marshal of `[]WhereClause`, which stays correct as long as
    WhereClause stays JSON-round-trippable.

    so a pathological nested filter cannot spin the resolver. If you
    ever need deeper legitimate nesting (say, ObjectSet unions of
    filters), the cap is a one-line change but keep it bounded.

## 2026-04-12 - US-057 SSE Last-Event-ID replay via NATS sequence
- New `Sequence uint64` field on `funnel.BroadcastEvent` (json tag
  `sequence,omitempty`) carries the NATS stream sequence through the
  fan-out hub so SSE clients can resume after a disconnect.
- `pkg/funnel.Broadcast` now maintains a bounded ring buffer (default
  `DefaultBroadcastReplayCapacity = 1024` entries) of the most recent
  events. `NewBroadcastWithReplay(ringCapacity int)` lets operators tune
  it; `NewBroadcast()` wraps it with the default.
- New `Broadcast.SubscribeWithReplay(buffer int, fromSeq uint64)`: under
  a single hub lock, snapshots every buffered event with
  `Sequence > fromSeq` into the new subscriber's pre-sized channel and
  registers it for live delivery — atomic replay + live attach so no
  event falls between the ring tail and the live head. `Subscribe(...)`
  delegates through with `fromSeq=0` for legacy call sites.
- `Publish` switched from RWMutex.RLock to Mutex.Lock because it now
  mutates the ring. Sends remain non-blocking (select + default) so a
  slow subscriber still cannot stall the publisher.
- `pkg/oss/subscribe_sse.go` reads the `Last-Event-ID` HTTP header, parses
  it as `uint64`, and calls `SubscribeWithReplay(16, fromSeq)`. Each
  outgoing frame emits `id: <Sequence>\n` before the `data:` line when
  `Sequence > 0` so the browser EventSource persists the cursor.
  Malformed header values silently degrade to `fromSeq=0` — never reject
  the request over a cursor parse error.
- `cmd/server/main.go` `FunnelConsumer.SetOnChange` forwarder now sets
  `BroadcastEvent.Sequence = e.Offset` (the NATS stream sequence the
  consumer stamps onto every ChangeEvent). In-process tests that publish
  directly with Sequence=0 still flow through but bypass ring storage.
- Red-first tests in `pkg/oss/subscribe_sse_test.go`:
  - `TestSSEReplayFromLastEventID`: pre-seeds 3 events (seq 10/11/12)
    BEFORE any subscriber, reconnects with `Last-Event-ID: 10`, reads
    both `id:` and `data:` lines into a paired `sseIDFrame`, asserts
    replay of 11+12 followed by a live event at seq 13.
  - `TestSSEReplayRingBufferSkipsSeenEvents`: supplies a Last-Event-ID
    larger than every ring entry and asserts no replay arrives.
- Files changed:
  - pkg/funnel/broadcast.go (Sequence field + ring buffer + SubscribeWithReplay + Publish rewrite)
  - pkg/oss/subscribe_sse.go (Last-Event-ID parse + SubscribeWithReplay wiring + `id:` line emit)
  - pkg/oss/subscribe_sse_test.go (2 red-first tests + sseIDFrame helper)
  - cmd/server/main.go (forward e.Offset → Sequence in SetOnChange)
  - scripts/ralph/prd.json (US-057 passes=true)
- Checks: `go test ./pkg/oss/ -run SSEReplay -v` green; `go test
  ./pkg/funnel/ ./pkg/oss/ ./cmd/server/ -race` clean; `go test ./...`
  all packages green; `go vet ./...` clean; `gofmt -l` clean on edited
  files.
- **Learnings for future iterations:**
  - `funnel.Broadcast.Publish` MUST hold the hub mutex across the fan-out
    loop — an earlier draft snapshotted the sub channel slice under lock
    and sent outside, but that races Unsubscribe/close and panics with
    "send on closed channel" under the concurrent subscribe/unsubscribe
    stress test (TestBroadcast_Concurrent_SubscribeUnsubscribe). Channel
    sends stay non-blocking via `select default`, so holding the lock
    cannot deadlock the publisher even with a slow subscriber.
  - `SubscribeWithReplay` pre-allocates `max(buffer, replay+buffer)` slots
    so the ring replay is loaded into the returned channel without
    blocking the caller thread. Any event that arrives after
    SubscribeWithReplay returns goes through the live Publish fan-out
    exactly once — the ring entry for that sequence will NOT be
    re-replayed because we atomically registered the subscription under
    the same lock that read the ring. This is the invariant that makes
    Last-Event-ID reconnect gap-free.
  - Out-of-order Sequence on Publish is silently dropped from ring
    storage (guarded by `event.Sequence > lastSeq`). The NATS consumer
    forwards ChangeEvents in stream order, so any out-of-order arrival
    means an in-process caller that didn't set Sequence — the dedupe is
    defensive rather than needed today.
  - SSE protocol: the client's EventSource transmits its cursor via
    `Last-Event-ID` request header on RECONNECT. The server emits it as
    `id: <value>\n` on each frame. The id persists across subsequent
    `data:` lines until overwritten (spec), which is why the test
    reader tracks `currentID` outside the per-line loop. A fresh
    subscribe without the header gets `fromSeq=0` which replays every
    ring entry — caller code may want to switch to "start from live
    tail" for first connect; currently the default is replay-all because
    missed events at startup of the frontend are still valuable to the
    UI.
  - Adding a field to `BroadcastEvent` has zero breakage for legacy
    in-process tests that use positional struct construction because
    the existing tests use KEYED literals (the standard codebase style).
    New fields should always be documented with `json:",omitempty"` so
    the wire shape stays backwards compatible if the event ever flows
    through JSON.
